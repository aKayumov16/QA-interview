# 🐍 Тема: Введение (Introduction)

### 💡 Что такое Python?
Python — это **высокоуровневый** язык программирования с **интерпретируемой** природой. 

*   **Высокоуровневый:** Ты пишешь код, похожий на английский язык. Тебе не нужно управлять памятью вручную (как в C) или следить за адресами ячеек процессора.
*   **Интерпретируемый:** Код не превращается в машинный код сразу (как в C++). Специальная программа — **интерпретатор** — читает твой код строка за строкой и выполняет его «на лету».
*   **Мультипарадигменный:** В Python можно писать в процедурном стиле (просто последовательность команд), в объектно-ориентированном (ООП) или функциональном стиле.

### ⚙️ Как это работает «под капотом» (Nuance Alert!)
Многие думают, что Python — это чистая интерпретация. Это не совсем так. Процесс выглядит так:
1.  **Исходный код** (`.py`) $\to$
2.  **Компиляция в байт-код** (невидимый код, который понимает Python) $\to$
3.  **Виртуальная машина Python (PVM)** $\to$ исполнение.

*Нюанс:* Байт-код сохраняется в папках `__pycache__` в виде файлов `.pyc`. Это нужно для того, чтобы при следующем запуске не тратить время на компиляцию, если исходный код не менялся.

### 🛠 Инструментарий профи
Чтобы не превратить свой компьютер в свалку библиотек, Senior всегда использует:
1.  **Pip:** Менеджер пакетов. Устанавливает чужие библиотеки (например, `pip install requests`).
2.  **Venv (Virtual Environment):** Изоляция проектов. **Золотое правило:** никогда не устанавливай библиотеки глобально в систему. Для каждого проекта создавай свое «пузырь» (виртуальное окружение). Это предотвращает конфликты версий (когда одному проекту нужен Django 3, а другому — Django 4).
3.  **PEP 8:** Это «конституция» Python. Стандарт оформления кода. Если твой код не соответствует PEP 8, коллеги на код-ревью тебя «съедят». (Сюда входят отступы в 4 пробела, правильные имена переменных и т.д.).

### 📜 Философия: The Zen of Python
В Python есть встроенная философия. Если ты введешь в консоли Python команду `import this`, ты увиди  **Zen of Python**. 
*Главные мысли:* «Простое лучше, чем сложное», «Явное лучше, чем неявное», «Читаемость имеет значение».

**О:** Это руководство по написанию чистого и единообразного кода на Python. Оно определяет правила отступов, именования классов, функций и длины строк, чтобы любой разработчик в мире мог легко читать твой код.

# 🧠 Шпаргалка: Типы данных в Python

В Python всё является **объектом**. Когда ты создаешь переменную, ты не выделяешь память под «число», ты создаешь объект в памяти, а переменная лишь хранит ссылку на него.

Главное разделение всех типов, которое нужно знать наизуб: **Mutable (Изменяемые)** и **Immutable (Неизменяемые)**.

---

## 1. Неизменяемые типы (Immutable)
*Если ты попытаешься изменить такой объект, Python просто создаст новый объект в памяти с новым значением.*

*   **`int` (Integer):** Целые числа. В Python нет предела размеру числа (оно ограничено только твоей оперативной памятью). Забудь про переполнение `int32/int64`, как в C++.
*   **`float` (Floating point):** Числа с плавающей точкой. Используют стандарт IEEE 754. 
    *   ⚠️ **Нюанс:** Из-за особенностей двоичной системы нельзя доверять точности (например, `0.1 + 0.2 != 0.3`). Для денег используй модуль `decimal`.
*   **`bool` (Boolean):** `True` и `False`. По сути, это подтип `int`, где `True == 1`, а `False == 0`.
*   **`str` (String):** Строки. Это неизменяемая последовательность символов Unicode. Любая операция над строкой (например, `.upper()`) создает **новую** строку.
*   **`tuple` (Кортеж):** Упорядоченная коллекция элементов. 
    *   **Зачем:** Быстрее списков и защищает данные от случайного изменения. Может содержать любые типы данных.
*   **`frozenset`:** Неизменяемая версия множества. Можно использовать как ключ в словаре (в отличие от обычного `set`).

---

## 2. Изменяемые типы (Mutable)
*Ты можешь менять содержимое объекта, не меняя его адрес в памяти.*

*   **`list` (Список):** Динамический массив. Позволяет хранить элементы разных типов.
    *   ⚠️ **Нюанс:** Добавление в конец (`append`) — это быстро ($O(1)$), но вставка в начало или середину — медленно ($O(n)$), так как Python приходится сдвигать все остальные элементы.
*   **`dict` (Словарь):** Хэш-таблица. Хранит пары `ключ: значение`. 
    *   ⚠️ **Нюанс:** Ключом может быть только **неизменяемый (hashable)** тип (например, `str`, `int`, `tuple`). Список (`list`) использовать как ключ нельзя.
*   **`set` (Множество):** Неупорядоченная коллекция **уникальных** элементов.
    *   **Зачем:** Идеально для удаления дубликатов и проверки наличия элемента (проверка `x in my_set` работает мгновенно — $O(1)$).

---

## 🛠 Инструменты проверки
Для профессиональной работы используй эти функции:
*   `type(obj)` — возвращает точный тип объекта.
*   `isinstance(obj, type)` — **рекомендуемый способ**. Проверяет, является ли объект экземпляром указанного класса (учитывает наследование).

---

## ⚠️ Главные «подводные камни» (Senior Tips)

1.  **Ловушка изменяемых аргументов по умолчанию:**
    Никогда не используй пустой список как значение аргумента функции: `def func(data=[])`. Список создается один раз при определении функции и будет «жить» между всеми вызовами, накапливая данные. Используй `data=None`.

2.  **Сравнение `==` vs `is`:**
    *   `==` проверяет **равенство значений** (содержимое одинаковое).
    *   `is` проверяет **идентичность объектов** (ссылаются ли они на одну и ту же ячейку в памяти).

3.  **Сложность операций (Big O):**
    Если тебе нужно часто проверять, есть ли элемент в коллекции — используй `set`. Если будешь искать в `list`, твой код будет тормозить на больших данных.

## ❓ FAQ (Частые вопросы на собеседовании)

**В: Можно ли использовать список как ключ в словаре?**
**О:** Нет. Ключ должен быть *hashable* (иметь постоянный хэш). Список — изменяемый тип, его содержимое может измениться, что разрушит структуру хэш-таблицы. Используй `tuple`.

**В: В чем разница между `append()` и `extend()` в списках?**
**О:** `append(obj)` добавляет объект целиком (даже если это другой список, он станет одним элементом). `extend(iterable)` берет каждый элемент из итерируемого объекта и добавляет их по отдельности.

**В: Что такое динамическая типизация?**
**О:** Это значит, что тип переменной определяется не в момент написания кода, а в момент присвоения значения. Тебе не нужно объявлять `int x`, ты просто пишешь `x = 5`. Но помни: это накладывает ответственность за проверку типов на тебя.

**В: Почему `0.1 + 0.2 != 0.3`?**
**О:** Потому что числа с плавающей точкой хранятся в двоичном виде, и некоторые десятичные дроби (как 0.1) невозможно представить в двоичной системе абсолютно точно — получается бесконечная дробь, которая обрезается.

# 🧠 Тема: Переменные и динамическая типизация

### 1. Суть: Что такое переменная в Python?
Забудь про определение из учебников по C++, где переменная — это «ячейка памяти, в которой лежит значение». В Python всё иначе.

**Переменная в Python — это не контейнер, а ярлык (ссылка).**
В памяти компьютера существует **объект** (число, строка, список), и у него есть адрес. Переменная — это просто имя, которое «приклеено» к этому объекту.

### 2. Динамическая типизация
Python — язык с **динамической типизацией**. Это значит:
*   Тебе не нужно заранее говорить: «Эта переменная будет числом».
*   Тип данных привязан к **объекту**, а не к имени.
*   Ты можешь переклеить ярлык с одного объекта на другой совершенно другого типа в любой момент программы.

```python
x = 10      # Теперь 'x' указывает на объект типа int (целое число)
x = "Hello" # Теперь тот же ярлык 'x' указывает на объект типа str (строка)
```

### 3. Синтаксис и правила именования (PEP 8)
*   **Имена:** Используй `snake_case` (маленькие буквы, слова через подчеркивание).
*   **Запреты:** Нельзя начинать с цифр, нельзя использовать зарезервированные слова (`if`, `while`, `class` и т.д.).
*   **Рекомендация:** Имя должно описывать суть данных (не `a = 86400`, а `seconds_in_day = 86400`).

### 4. Нюансы от Senior-а (Важно!)

#### А) Ссылка на один и тот же объект
Поскольку переменная — это ссылка, при копировании переменной ты не создаешь новый объект, ты просто создаешь второй ярлык для того же самого объекта. Это ведет к классическим багам с изменяемыми типами (списками, словарями).

```python
a = [1, 2, 3]
b = a          # 'b' теперь указывает на тот же список, что и 'a'
b.append(4)
print(a)       # Выведет [1, 2, 3, 4]! Список изменился везде.
```

#### Б) Разница между `==` и `is` (Критично!)
Это база, на которой валятся джуны:
*   **`==` (Equality):** Проверяет **значение**. Содержимое объектов одинаковое?
*   **`is` (Identity):** Проверяет **адрес в памяти**. Это один и тот же объект?

```python
list1 = [1, 2]
list2 = [1, 2]

print(list1 == list2) # True (значения равны)
print(list1 is list2) # False (это два разных списка в разных ячейках памяти)
```

#### В) Мутабельность (Изменяемость)
Типы данных делятся на:
*   **Immutable (Неизменяемые):** `int`, `float`, `str`, `tuple`, `bool`. Если ты «меняешь» строку, Python на самом деле создает в памяти новую строку.
*   **Mutable (Изменяемые):** `list`, `dict`, `set`. Можно менять содержимое объекта, не меняя его адрес.

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Можно ли в Python объявить переменную без значения?**
**О:** Нет. В отличие от C++, ты не можешь просто написать `int x;`. Ты обязан присвоить переменной объект (хотя бы `None`), иначе возникнет `NameError`.

**В: Что такое `None`?**
**О:** Это специальный объект типа `NoneType`, который представляет собой «пустоту» или отсутствие значения. Это не ноль и не пустая строка, это самостоятельный объект.

**В: Если типизация динамическая, почему все говорят про Type Hinting (аннотации типов)?**
**О:** Аннотации (`x: int = 10`) не меняют поведение Python (он всё равно проглотит строку вместо числа), но они нужны **тебе** и твоим инструментам (IDE, PyCharm, mypy). Это делает код предсказуемым и помогает ловить ошибки до запуска программы.

**В: Почему `a = b = c = 0` — это безопасно, а `a = b = c = []` — это ловушка?**
**О:** В первом случае все три переменные указывают на один и тот же число `0` (неизменяемый тип). Во втором случае все три переменные указывают на **один и тот же список**. Изменишь `a`, и `b` с `c` изменятся следом.

# 🛠 Шпаргалка: Операторы в Python

Операторы — это инструменты, которые заставляют данные взаимодействовать друг с другом. В Python их можно разделить на несколько ключевых групп.

## 1. Арифметические операторы (Arithmetic)
Используются для математических вычислений.

| Оператор | Название | Пример | Результат | Нюанс Senior-а |
| :--- | :--- | :--- | :--- | :--- |
| `+` | Сложение | `5 + 2` | `7` | Работает не только с числами, но и со строками/списками (конкатенация). |
| `-` | Вычитание | `5 - 2` | `3` | |
| `*` | Умножение | `5 * 2` | `10` | При работе со списками `[1] * 3` создаст список из трех одинаковых элементов. |
| `/` | Деление | `5 / 2` | `2.5` | **Всегда** возвращает тип `float`, даже если деление нацело. |
| `//` | Целочисленное деление | `5 // 2` | `2` | Округляет результат **вниз** (к меньшему целому). Внимательно с отрицательными числами: `-5 // 2` будет `-3`. |
| `%` | Остаток от деления | `5 % 2` | `1` | Полезно для проверки четности (`x % 2 == 0`). |
| `**` | Возведение в степень | `5 ** 2` | `25` | Имеет самый высокий приоритет. |

---

## 2. Операторы сравнения (Comparison)
Результат всегда `True` или `False`.

*   `==` (Равно), `!=` (Не равно)
*   `>` (Больше), `<` (Меньше)
*   `>=` (Больше или равно), `<=` (Меньше или равно)

**💡 Senior Tip: Chaining (Цепочки сравнений).** 
В Python можно писать красиво: `1 < x < 10`. Это не просто два сравнения, это одна операция, которая проверяет, входит ли `x` в диапазон. В других языках пришлось бы писать `x > 1 and x < 10`.

---

## 3. Логические операторы (Logical)
Используются для объединения условий.

*   `and` (Логическое И): Возвращает `True`, если **оба** условия верны.
*   `or` (Логическое ИЛИ): Возвращает `True`, если **хотя бы одно** условие верно.
*   `not` (Логическое НЕ): Инвертирует результат.

**⚠️ Нюанс: Short-circuit evaluation (Ленивые вычисления).** 
Python — очень умный. 
- В `A and B`, если `A` — это `False`, Python **даже не будет смотреть** на `B`. Он уже знает, что результат будет `False`.
- В `A or B`, если `A` — это `True`, Python не проверяет `B`.
*Это критически важно для оптимизации и предотвращения ошибок (например, чтобы не вызвать деление на ноль во второй части выражения).*

---

## 4. Операторы идентичности и принадлежности
Самые важные для понимания работы памяти.

*   `is` (Идентичность): Проверяет, указывают ли две переменные на **один и тот же объект в памяти**.
*   `in` (Принадлежность): Проверяет, содержится ли элемент в последовательности (строке, списке, кортеже).

**⚠️ Ошибка новичка: `is` vs `==`.** 
`==` проверяет **значение** (содержимое), а `is` — **адрес** в памяти. 
`[1, 2] == [1, 2]` $\rightarrow$ `True`.
`[1, 2] is [1, 2]` $\rightarrow$ `False` (это два разных списка, просто похожих).

---

## 5. Операторы присваивания (Assignment)
Помимо обычного `=`, есть сокращенные формы:
`x += 5`, `x -= 3`, `x *= 2` и т.д.

**⚠️ Нюанс с мутабельными объектами:** 
Когда ты делаешь `list1 += [4]`, Python изменяет **тот же самый** список на месте (in-place). Это работает иначе, чем `list1 = list1 + [4]`, который создает новый объект.

---

## ❓ FAQ (Часто задаваемые вопросы)

**В: В чем разница между `/` и `//`?**
О: `/` — это всегда деление с плавающей точкой (результат `2.5`). `//` — это целочисленное деление, которое отбрасывает дробную часть (результат `2`), но помни про округление вниз при отрицательных числах!

**В: Что такое "Truthiness" (Истинность) в Python?**
О: В Python почти любой объект можно использовать в логическом операторе. `0`, `None`, `[]` (пустой список), `""` (пустая строка) — это `False`. Все остальное — `True`.

**В: Почему нельзя использовать `is` для сравнения чисел или строк?**
О: Потомум что `is` проверяет ID объекта в памяти. Python иногда кэширует маленькие числа и короткие строки, поэтому `a is b` может сработать случайно, но на больших данных или других типах это приведет к трудноуловимым багам. Всегда используй `==` для сравнения значений.

**В: Как работает оператор `in` со строками?**
О: Он ищет подстроку. `"cat" in "concatenate"` вернет `True`. Это очень быстрая и эффективная операция в Python.

# 🧵 Тема: Строки (Strings)

**Суть:** В Python `str` — это **неизменяемая (immutable)** последовательность символов Unicode. Это значит, что ты не можешь изменить символ внутри существующей строки; любая операция над строкой всегда создает **новую** строку в памяти.

### 1. Создание и синтаксис
```python
s1 = 'Одинарные кавычки'
s2 = "Двойные кавычки"
s3 = """Многострочная строка
позволяет писать текст
с переносами строк"""

# Raw strings (сырые строки) — игнорируют escape-последовательности (\n, \t). 
# Незаменимы для путей в Windows и регулярных выражений.
path = r"C:\users\name\documents" 

# Escape-символы: \n (новая строка), \t (табуляция), \\ (обратный слэш), \' (кавычка)
```

### 2. Срезы (Slicing) — Магия индексов
Срез работает по формуле: `[start : stop : step]`
*   `start`: Индекс начала (включительно).
*   `stop`: Индекс конца (**не включая его!**).
*   `step`: Шаг.

```python
s = "Python"

print(s[0:2])   # 'Py'
print(s[:4])    # 'Pyth' (от начала до 4-го индекса)
print(s[2:])    # 'thon' (от 2-го до конца)
print(s[::-1])  # 'nohtyP' (разворот строки — классический прием)
print(s[::2])   # 'Pto' (каждый второй символ)
```

### 3. Основные методы (Твой арсенал)
**Преобразование регистра:**
*   `.upper()`, `.lower()` — в верхний/нижний регистр.
*   `.capitalize()` — первая буква строки заглавная.
*   `.title()` — каждая первая буква слова заглавная.

**Поиск и проверка:**
*   `.find(sub)` — возвращает индекс первого вхождения или `-1`, если не найдено (безопасно).
*   `.index(sub)` — то же самое, но кидает ошибку `ValueError`, если не найдено.
*   `.startswith(prefix)` / `.endswith(suffix)` — проверка начала/конца строки (возвращает `bool`).
*   `.count(sub)` — сколько раз подстрока встречается в строке.

**Очистка и разделение:**
*   `.strip()` — удаляет пробелы (и другие символы) с обоих концов. `.lstrip()` / `.rstrip()` — только слева или справа.
*   `.split(sep)` — разбивает строку в список по разделителю `sep`.
*   `" ".join(list_of_strs)` — **Критически важный метод!** Собирает список строк в одну, разделяя их указанным символом.

### 4. Форматирование (F-strings — стандарт индустрии)
Забудь про старый `%` или `.format()`, если не работаешь с очень древним кодом. Используй **f-strings** (появились в Python 3.6).

```python
name = "Алексей"
age = 25

# Быстро, читаемо, эффективно
print(f"Привет, меня зовут {name}, мне {age} лет.")

# Можно выполнять выражения прямо внутри!
print(f"Через 5 лет мне будет {age + 5}")

# Форматирование чисел (округление до 2 знаков)
pi = 3.14159
print(f"Число Пи: {pi:.2f}")
```

### ⚠️ Нюансы и "Подводные камни" (Senior Tips)

1.  **Проблема производительности (Конкатенация в цикле):**
    *   **Плохо:** `s += char` внутри цикла. Так как строки неизменяемы, на каждой итерации Python создает новую строку и копирует туда старые данные. Это превращает сложность алгоритма из $O(n)$ в $O(n^2)$.
    *   **Хорошо:** Накапливай элементы в списке `res.append(char)`, а в конце сделай `''.join(res)`. Это работает максимально быстро.

2.  **Сравнение `is` vs `==`:**
    *   Никогда не сравнивай строки через `is`. `is` проверяет идентичность объектов в памяти (адрес), а `==` проверяет равенство содержимого. Для строк всегда используй `==`.

3.  **Пустая строка:**
    *   В Python пустая строка `""` при приведении к логическому типу (`bool("")`) всегда дает `False`. Это удобно для проверок: `if not my_string: print("Строка пуста")`.

# 🧠 Шпаргалка: Условные операторы (Conditional Statements)

Условные операторы — это «развилки» в твоем коде. Они позволяют программе принимать решения на основе условий: если условие истинно (`True`), выполняется один блок кода, если ложно (`False`) — другой.

### 1. Базовая конструкция: `if`, `elif`, `else`
Это фундамент. Главное правило Python: **отступы (indentation) определяют принадлежность блока кода к условию.**

```python
age = 20

if age < 18:
    print("Доступ запрещен")  # Выполнится, если age < 18
elif age == 18:
    print("Поздравляем, вы стали совершеннолетним!") # Выполнится, если age ровно 18
else:
    print("Доступ разрешен")  # Выполнится во всех остальных случаях
```

*   `if`: Проверяет первое условие.
*   `elif` (сокращение от *else if*): Позволяет проверять цепочку условий, если предыдущие не сработали. Можно использовать сколько угодно раз.
*   `else`: «Запасной вариант», срабатывает, если ни одно из условий выше не подошло.

---

### 2. Операторы сравнения и логики
Чтобы строить условия, нам нужны кирпичики:

**Операторы сравнения:**
* `==` (равно), `!=` (не равно)
* `>`, `<`, `>=`, `<=` (больше, меньше, больше или равно, меньше или равно)

**Логические операторы (связки):**
* `and`: Истина, только если **оба** условия верны.
* `or`: Истина, если хотя бы **одно** условие верно.
* `not`: Инверсия (превращает `True` в `False` и наоборот).

---

### 3. Pythonic Way: Truthiness (Истинность)
Senior-разработчик не пишет `if len(my_list) > 0:`. Он пишет `if my_list:`.
В Python любой объект можно привести к `bool`. 

**Всегда `False` (Ложные значения):**
* `None`
* `False`
* Число ноль: `0`, `0.0`
* Пустые коллекции: `""` (пустая строка), `[]` (пустой список), `{}` (пустой словарь), `set()` (пустое множество).

**Всегда `True`:**
* Любое непустое значение, любое число, кроме нуля.

---

### 4. Тернарный оператор (Условие в одну строку)
Когда нужно быстро присвоить переменной значение в зависимости от условия. Это делает код компактным.

```python
# Синтаксис: [значение_если_True] if [условие] else [значение_если_False]
status = "Adult" if age >= 18 else "Minor"
```

---

### 5. Продвинутая фишка: `match/case` (Python 3.10+)
Это не просто `if/elif`, это **Structural Pattern Matching**. Он гораздо мощнее, так как умеет «заглядывать» внутрь структур данных.

```python
command = "move left"

match command.split():
    case ["move", direction]:
        print(f"Двигаемся на {direction}")
    case ["stop"]:
        print("Остановка")
    case _:
        print("Неизвестная команда") # Аналог else (wildcard)
```

---

### ⚠️ Нюансы и «Подводные камни»

1.  **Short-circuit evaluation (Ленивые вычисления):** Python — ленивый парень. 
    *   В `and`: если первое условие `False`, второе даже не будет проверяться (результат всё равно будет `False`).
    *   В `or`: если первое условие `True`, второе не проверяется (результат уже точно `True`).
    *   *Зачем это знать?* Это позволяет писать безопасные проверки: `if obj is not None and obj.value > 0:`. Если бы не ленивость, программа бы упала на `obj.value`, если `obj` равен `None`.

2.  **Приоритет операций:** `not` имеет самый высокий приоритет, затем `and`, затем `or`. Всегда используй скобки `()`, чтобы код был читаемым и не возникло логической ошибки.
    *   Плохо: `if a or b and c` (непонятно на глаз).
    *   Хорошо: `if a or (b and c)`.

# 🔄 Тема: Циклы (Loops)

Циклы нужны для повторения блока кода. В Python есть два основных игрока: `for` и `while`.

### 1. Цикл `for` (Итерация по объектам)
В Python `for` — это не просто счетчик (как в C++), это **итератор**. Он проходит по элементам любого *iterable* объекта (список, строка, словарь, кортеж).

**Синтаксис:**
```python
for item in iterable:
    # код
```

**Основные инструменты внутри `for`:**
*   `range(start, stop, step)` — генератор последовательности чисел. 
    *   *Нюанс:* `stop` не включается в диапазон!
    *   `range(5)` $\rightarrow$ `0, 1, 2, 3, 4`.
*   `enumerate(iterable, start=0)` — когда нужен и индекс, и само значение. **Золотой стандарт** вместо `range(len(arr))`.
*   `zip(list1, list2)` — параллельная итерация по нескольким спискам одновременно.

### 2. Цикл `while` (Условие)
Работает до тех пор, пока условие истинно (`True`). Используется, когда мы **не знаем заранее**, сколько раз придется повторить действие.

**Синтаксис:**
```python
while condition:
    # код
```
*   **Опасность:** Если условие никогда не станет `False`, ты получишь **бесконечный цикл** и зависший процесс. Всегда проверяй, есть ли внутри цикла механизм изменения условия (например, инкремент счетчика).

### 3. Управление циклом (Control Statements)
Это «ручное управление» поведением:
*   `break` — немедленный выход из цикла. Полная остановка.
*   `continue` — пропуск текущей итерации. Код ниже `continue` в теле цикла не выполнится, цикл перейдет к следующему шагу.
*   `pass` — «пустышка». Ничего не делает. Нужна, чтобы код не выдавал синтаксическую ошибку, если тело цикла пока не написано.

### 4. Senior-фишка: Блок `else` в циклах
Мало кто помнит, но у `for` и `while` есть свой `else`.
*   **Логика:** Блок `else` выполняется **только если цикл завершился сам**, без прерывания через `break`.
*   **Зачем это нужно?** Идеально для поиска. Если нашли элемент — `break`, если прошли весь цикл и не нашли — сработал `break` и мы попали в `else`.

```python
for n in [1, 2, 3]:
    if n == 5:
        print("Нашли!")
        break
else:
    print("Не нашли, всё прошли до конца") # Сработает здесь
```

### ⚠️ Подводные камни (Nuances)
1.  **Изменение коллекции во время итерации:** **НИКОГДА** не удаляй элементы из списка, по которому прямо сейчас идет цикл `for`. Это приведет к пропуску элементов или непредсказуемому поведению. 
    *   *Решение:* Итерируйся по копии списка `for item in my_list[:]` или создавай новый список через *List Comprehension*.
2.  **Сложность (Complexity):** Вложенные циклы — это зло. Цикл в цикле превращает сложность из $O(n)$ в $O(n^2)$. Если данных много, программа «умрет». Всегда ищи способы заменить вложенный цикл на использование `set` или `dict` (сложность поиска в них $O(1)$).

### ❓ FAQ (Частые вопросы)

**В: В чем разница между `for` и `while`?**
**О:** `for` используется, когда ты знаешь границы (кол-во элементов, диапазон). `while` — когда ждешь наступления события или выполнения условия (например, пока пользователь не нажмет "Выход").

**В: Что лучше: `for i in range(len(my_list))` или `for item in my_list`?**
**О:** Вторым вариантом. Первый — это «стиль C», он медленнее и менее читаем в Python. Если нужен индекс, используй `enumerate`.

**В: Как прервать бесконечный цикл, если я его случайно запустил в терминале?**
**О:** Нажми комбинацию клавиш `Ctrl + C` (KeyboardInterrupt). Это стандартный способ остановить выполнение скрипта.

**В: Можно ли использовать `else` вместе с `continue`?**
**О:** Да, но это редко имеет смысл. `else` реагирует только на отсутствие `break`. `continue` просто перекидывает управление на начало цикла, не влияя на логику `else`.

# 🔄 Шпаргалка: Управление циклами в Python

Циклы нужны для автоматизации повторяющихся действий. В Python есть два основных вида циклов (`for` и `while`) и три ключевых инструмента управления их ходом (`break`, `continue`, `pass`).

## 1. Основные типы циклов

### Цикл `for` (Итерация по объекту)
Используется, когда мы заранее знаем, сколько раз нужно выполнить код или когда у нас есть последовательность (список, строка, диапазон).
*   **Суть:** «Для каждого элемента в этой коллекции сделай вот это».
*   **Синтаксис:** `for item in iterable:`

### Цикл `while` (Условие)
Используется, когда мы не знаем заранее, сколько итераций потребуется, и ждем выполнения определенного условия.
*   **Суть:** «Пока это условие истинно (`True`), делай вот это».
*   **Синтаксис:** `while condition:`

---

## 2. Инструменты управления (Control Statements)

Это «руль» твоего цикла.

| Команда | Что делает | Когда использовать |
| :--- | :--- | :--- |
| **`break`** | Полностью прерывает цикл. | Когда цель достигнута и продолжать поиск/работу нет смысла. |
| **`continue`** | Пропускает текущую итерацию и переходит к следующей. | Когда текущий элемент «плохой» или не подходит под критерий, и его нужно просто пропустить. |
| **`pass`** | Ничего не делает (заглушка). | Когда синтаксис требует наличия тела цикла, но логику ты напишешь позже. |

---

## 3. Senior-фишки: То, что отличает профи

### А) Блок `else` в циклах (Редкая, но мощная штука)
В Python у циклов `for` и `while` может быть блок `else`.
*   **Нюанс:** Код в `else` выполнится **только в том случае, если цикл завершился сам по себе** (не был прерван командой `break`).
*   **Зачем:** Идеально для проверки: «Нашли ли мы что-то?». Если нашли — `break`, если прошли весь список и не вышли — сработал `else`.

### Б) Умная итерация: `enumerate` и `zip`
Не используй счетчик `i = 0; i += 1` внутри `for`. Это плохой тон.
*   **`enumerate(iterable)`**: Если нужен и сам элемент, и его индекс.
*   **`zip(list1, list2)`**: Если нужно идти по двум (или более) спискам параллельно.

## 4. Подводные камни (Pitfalls) ⚠️

1.  **Бесконечный цикл `while`:** Самая классическая ошибка — забыть обновить условие внутри `while`. Программа «зависнет», потребляя ресурсы.
2.  **Изменение списка во время итерации:** **Никогда** не удаляй элементы из списка, по которому ты прямо сейчас идешь циклом `for`. Это приведет к пропуску элементов или ошибкам. 
    *   *Решение:* Либо создавай новый список (List Comprehension), либо итерируйся по копии списка `for item in my_list[:]`.
3.  **Сложные вложенные циклы:** Если у тебя цикл внутри цикла, внутри еще одного — это «код-спагетти». Это убивает производительность ($O(n^2)$). Старайся выносить логику во вложенных циклах в отдельные функции.

# 🚀 Шпаргалка: Новый синтаксис Python (Modern Python)

Современный Python стремится к **декларативности** (писать *что* делать, а не *как*) и уменьшению количества лишних строк кода (boilerplate).

### 1. Structural Pattern Matching (`match/case`) — Python 3.10+
Это не просто `switch/case` из C++ или Java. Это мощный инструмент **деструктуризации** данных. Он умеет «заглядывать» внутрь объектов, списков и словарей.

*   **Синтаксис:**
```python
match command:
    case "quit":
        exit()
    case f"move {direction}":  # Извлечение значения из строки
        print(f"Moving to {direction}")
    case [x, y]:                # Распаковка списка (pattern matching)
        print(f"Coordinates: {x}, {y}")
    case _:                     # Wildcard (аналог default/else)
        print("Unknown command")
```

*   **Нюанс:** `match` проверяет не только значение, но и **структуру**. Если ты ждешь список из двух элементов `[x, y]`, а придет список из трех — этот `case` не сработает. Это гораздо безопаснее обычных `if/else`.

---

### 2. Walrus Operator (`:=`) — Python 3.8+
«Морж» позволяет присвоить значение переменной прямо внутри выражения.

*   **Синтаксис:**
```python
# Старый стиль (двойное вычисление или лишняя строка)
data = get_data()
if data:
    process(data)

# С моржом (лаконично)
if (data := get_data()):
    process(data)
```

*   **Нюанс:** Не злоупотребляй. Если в одной строке слишком много «моржей», код превращается в нечитаемый ребус. Используй его только там, где это реально экономит строку и сохраняет ясность (например, в циклах `while`).

---

### 3. Union Operators для словарей (`|` и `|=`) — Python 3.9+
Раньше для слияния словарей приходилось использовать `update()` или распаковку `{**d1, **d2}`. Теперь всё проще.

*   **Синтаксис:**
```python
dict_a = {"name": "Alice", "role": "admin"}
dict_b = {"role": "user", "age": 25}

# Создание нового словаря (Merge)
merged = dict_a | dict_b  
# Результат: {'name': 'Alice', 'role': 'user', 'age': 25} (ключи из правого приоритетнее)

# Обновление существующего (Update)
dict_a |= dict_b 
```

*   **Нюанс:** Оператор `|` создает **новый** объект, а `|=` изменяет **текущий**. Это важно для понимания мутабельности.

---

### 4. Улучшенные f-strings — Python 3.12+
F-строки стали невероятно гибкими. Теперь внутри них можно использовать любые кавычки, многострочные выражения и даже обратные слеши.

*   **Синтаксис:**
```python
# Раньше нельзя было использовать одинаковые кавычки внутри f-string
songs = ['Yesterday', 'Hello', 'Help']
print(f"List: {', '.join([s.upper() for s/songs])}") # Теперь работает без ошибок

# Можно вкладывать f-строки друг в друга (nested f-strings)
name = "Python"
print(f"Language: {f'{name.upper()} is awesome'}")
```

*   **Нюанс:** Несмотря на мощь, старайся не превращать f-строку в полноценный алгоритм. Если логика внутри `{}` занимает больше одной строки — выноси её в отдельную функцию/переменную. Чистый код важнее короткого.

# 🧠 Шпаргалка: Итерация по структурам данных

Итерация — это процесс последовательного перебора элементов коллекции. В Python всё строится на протоколах **Iterable** (то, что можно перебрать) и **Iterator** (объект, который управляет процессом перебора).

### 1. Основы: Цикл `for`
Цикл `for` в Python — это не просто счетчик, как в C++. Это инструмент, который берет объект и запрашивает у него следующий элемент до тех пор, пока они не закончатся.

*   **Списки, кортежи, строки, множества:**
    ```python
    items = [10, 20, 30]
    for item in items:
        print(item)  # Просто перебор значений
    ```

### 2. Итерация по Словарю (`dict`)
Словарь — это не просто последовательность, это пары `ключ: значение`. Есть три способа его «вскрыть»:

*   **По ключам (по умолчанию):** `for key in my_dict:`
*   **По значениям:** `for value in my_dict.values():`
*   **По парам (самый важный):** `for key, value in my_dict.items():` — это называется *распаковкой*.

> **Senior Tip:** Начиная с Python 3.7+, словари сохраняют порядок вставки элементов. Это важно для предсказуемости кода.

### 📜 3. Инструменты «Профи» (Built-in Functions)
Чтобы не писать костыли, используй встроенные функции. Это делает код чище и быстрее.

*   **`enumerate()` — когда нужен индекс:**
    Забудь про `for i in range(len(arr))`. Это плохой тон. Используй `enumerate`.
    ```python
    names = ["Alice", "Bob", "Charlie"]
    for idx, name in enumerate(names):
        print(f"{idx}: {name}") # 0: Alice, 1: Bob...
    ```

*   **`zip()` — параллельная итерация:**
    Если у тебя есть два списка одинаковой длины и их нужно обработать «парами».
    ```python
    ids = [1, 2, 3]
    users = ["admin", "guest", "editor"]
    for user_id, user_name in zip(ids, users):
            print(f"ID {user_id} belongs to {user_name}")
    ```

*   **`reversed()` — итерация в обратном порядке:**
    Не используй `items[::-1]` (это создает копию списка в памяти!). Используй `reversed()`, он возвращает итератор, не тратя лишнюю память.
    ```python
    for item in reversed([1, 2, 3]):
        print(item) # 3, 2, 1
    ```

### ⚠️ Главные нюансы и «Подводные камни»

1.  **Мутация во время итерации (Критическая ошибка!):**
    Никогда не удаляй элементы из списка прямо во время цикла `for` по этому же списку. Это приведет к пропуску элементов или ошибкам.
    *   *Как правильно:* Создай копию списка для итерации (`for item in my_list[:]`) или собирай новые элементы в новый список.

2.  **Одноразовость итераторов:**
    Объекты-итераторы (например, результат `zip`, `enumerate` или генератор) можно пройти **только один раз**. После того как цикл завершился, итератор «исчерпан». Если попробуешь запустить второй цикл по нему — он будет пустым.

3.  **Сложность (Complexity):**
    Помни, что итерация по `set` или `dict` работает быстро, но порядок элементов в `set` не гарантирован (хотя в современных версиях Python он стал более стабильным, полагаться на него нельзя).

### ❓ FAQ (Частые вопросы)

**В: В чем разница между Iterable и Iterator?**
**О:** *Iterable* — это объект, у которого есть метод `__iter__` (например, список). Он «знает», как создать итератор. *Iterator* — это объект, который имеет метод `__next__` и «помнит», на каком элементе он остановился.

**В: Что произойдет, если в `zip()` передать списки разной длины?**
**О:** Стандартный `zip()` остановится на самом коротком списке. Если тебе нужно дойти до конца самого длинного (заполнив пустоты), используй `itertools.zip_longest()`.

**В: Когда лучше использовать `while`, а когда `for`?**
**О:** Используй `for`, если ты заранее знаешь (или можешь вычислить) количество элементов или у тебя есть коллекция. Используй `while`, если цикл должен продолжаться до наступления какого-то условия (логического события), а не пока не кончатся элементы.

**В: Как эффективно перебрать очень большой файл?**
**О:** Не делай `.readlines()`, это загрузит весь файл в RAM. Используй итерацию по объекту файла: `for line in open('big_file.txt'):`. Это читает файл построчно, экономя память.

# 📜 Шпаргалка: Списки (Lists) в Python

**Списки** — это самая используемая структура данных в Python. Представь их как динамический массив: упорядоченная коллекция элементов, которую можно изменять (mutable).

### 1. Суть и создание
Список может содержать объекты любых типов (даже разные типы в одном списке) и может быть пустым.

```python
empty_list = []             # Самый быстрый способ
another_empty = list()     # Чуть медленнее, но полезно для приведения типов
numbers = [1, 2, 3, 4, 5]   # Инициализация значениями
mixed = [1, "Python", True, 3.14] # Гетерогенный список (разные типы)
```

### 2. Доступ к элементам (Indexing & Slicing)
В Python списки начинаются с **0**.

*   **Индексация:** `arr[0]` — первый, `arr[-1]` — последний.
*   **Срезы (Slicing):** `list[start:stop:step]`
    *   `stop` не включается в результат!
       *   `arr[1:4]` — элементы с индекса 1 по 3.
    *   `arr[::-1]` — **Senior trick:** быстрый способ развернуть список задом наперед.
    *   `arr[:3]` — первые три элемента.

### 3. Основные операции (Изменение)
Здесь важно различать, как мы добавляем и удаляем данные.

**Добавление:**
*   `.append(x)` — добавляет **один** объект в конец.
*   `.extend(iterable)` — расширяет список, добавляя все элементы из другого списка/кортежа (распаковывает их).
*   `.insert(index, x)` — вставляет элемент в конкретную позицию (тяжелая операция, так как нужно сдвигать остальные элементы).

**Удаление:**
*   `.pop(index)` — удаляет элемент по индексу и **возвращает** его. Если индекс не указан — удаляет последний.
*   `.remove(x)` — ищет и удаляет **первое вхождение** значения `x`. Выдаст ошибку, если `x` нет в списке.
*   `.clear()` — полностью очищает список.
*   `del arr[0]` — оператор удаления по индексу (не метод).

### 4. Полезные встроенные функции
*   `len(arr)` — длина списка.
*   `sorted(arr)` — возвращает **новый** отсодержимое списка, не меняя оригинал.
*   `arr.sort()` — сортирует **оригинальный** список (in-place). Экономит память.
*   `arr.count(x)` — сколько раз `x` встречается в списке.
*   `x in arr` — проверка наличия элемента (оператор `in`).

### 5. Pythonic Way: List Comprehensions
Вместо громоздких циклов `for`, используй генераторы списков. Это быстрее и чище.

```python
# Вместо этого:
squares = []
for i in range(10):
    squares.append(i**2)

# Пишем так:
squares = [i**2 for i in range(10) if i % 2 == 0] # Квадраты четных чисел
```

---

### ⚠️ Senior Nuances (Подводные камни)

1.  **Сложность операций (Big O):**
    *   `append()` — $O(1)$ (очень быстро).
    *   `pop()` (последний элемент) — $O(1)$.
    *   `insert()`, `pop(0)`, `remove()` — $O(n)$. Почему? Потому что Python приходится **сдвигать** все остальные элементы в памяти. Если тебе нужно часто удалять/добавлять в начало, используй `collections.deque`.

2.  **Копирование (Shallow vs Deep Copy):**
    *   `list_b = list_a` — это **НЕ копия**. Это ссылка на тот же объект. Изменишь `b`, изменится и `a`.
    *   `list_b = list_a.copy()` или `list(list_a)` — **Поверхностная копия** (shallow copy). Если внутри списка лежат другие списки, они все равно останутся общими.
    *   Для полной независимости используй `copy.deepcopy()`.

3.  **Мутация во время итерации:**
    *   **Никогда** не удаляй элементы из списка прямо во время цикла `for item in my_list:`. Это приведет к пропуску элементов. 
    *   *Решение:* Итерируйся по копии или создавай новый список через List Comprehension.

### ❓ FAQ (Частые вопросы на собеседовании)

**В: В чем разница между `append()` и `extend()`?**
**О:** `append` добавляет объект целиком (даже если это другой список, он станет вложенным). `extend` берет элементы из итерируемого объекта и добавляет их по одному.

**В: Что быстрее: `list.sort()` или `sorted(list)`?**
**О:** `list.sort()` быстрее, так как не создает новый объект и не тратит время на выделение памяти под него. Но помни, что он перезаписывает оригинал.

**В: Как проверить, пуст ли список?**
**О:** Самый Pythonic способ — `if not my_list:`. В Python пустые контейнеры приравниваются к `False`.

**В: Что произойдет, если вызвать `.remove()` для элемента, которого нет в списке?**
**О:** Вылетит ошибка `ValueError`. Всегда проверяй наличие через `if x in my_list:` или используй блок `try-except`.

# 📌 Шпаргалка: Кортежи (Tuples)

**Кортеж (tuple)** — это упорядоченная, **неизменяемая** последовательность элементов. Если список (`list`) — это блокнот, где можно стирать и дописывать, то кортеж — это запись в печатной книге: прочитал и всё.

### 🛠 Создание и синтаксис
```python
# Пустой кортеж
empty = ()

# Кортеж с элементами
tup = (1, 2, 3, "Python")

# Важный нюанс: Кортеж из одного элемента ОБЯЗАТЕЛЬНО требует запятую
single = (5,)  # Это кортеж
not_a_tuple = (5)  # Это просто integer в скобках!

# Упаковка (Tuple Packing) — создание без скобок
numbers = 1, 2, 3  # Python сам поймет, что это кортеж
```

### 🔍 Основные операции
*   **Доступ по индексу:** `tup[0]`, `tup[-1]` (как в списках).
*   **Срезы (Slicing):** `tup[1:3]` — получение подмножества.
*   **Распаковка (Unpacking):** 
    ```python
    point = (10, 20)
    x, y = point  # x=10, y=20
    ```
*   **Расширенная распаковка (Python 3+):**
    ```python
    data = (1, 2, 3, 4, 5)
    first, *middle, last = data  # first=1, middle=[2, 3, 4], last=5
    ```

### ⚙️ Доступные методы
У кортежей всего два метода, потому что менять их нельзя:
1.  `.count(x)` — считает, сколько раз `x` встречается в кортеже.
2.  `.index(x)` — возвращает индекс первого вхождения `x`.

---

### ⚠️ Нюансы и "Подводные камни" (Senior Level)

**1. Иллюзия неизменяемости (Mutable elements inside tuple)**
Сам кортеж нельзя изменить (нельзя добавить или удалить элементы), но если внутри него лежит **изменяемый** объект (например, список), то содержимое этого списка менять **можно**.
```python
tup = (1, 2, [3, 4])
tup[2].append(5)  # Это сработает! Кортеж всё еще хранит тот же самый список.
# Результат: (1, 2, [3, 4, 5])
```

**2. Хешируемость (Hashability)**
Кортеж может быть ключом в словаре (`dict`) или элементом множества (`set`) только в том случае, если **все его элементы сами являются неизменяемыми** (hashable).
```python
bad_tup = (1, 2, [3]) 
# d = {bad_tup: "error"}  # Вызовет TypeError: unhashable type: 'list'
```

**3. Производительность**
Кортежи работают чуть быстрее списков и занимают меньше памяти. В Python кортежи оптимизированы для работы с фиксированным набором данных. Используй их там, где данные не должны меняться.

---

### ❓ FAQ (Частые вопросы)

**В: Чем кортеж отличается от списка?**
**О:** Главное отличие — **immutability** (неизменяемость). Список можно менять на месте, кортеж — нет. Это влияет на безопасность данных, скорость и возможность использования в качестве ключа словаря.

**В: Зачем нужна запятая в `(5,)`?**
**О:** Без запятой Python интерпретирует выражение как математическое действие (просто число в скобках). Запятая — это единственный сигнал интерпретатору, что перед ним кортеж.

**В: Можно ли "изменить" кортеж?**
**О:** Напрямую — нет. Но можно создать новый кортеж путем конкатенации старого с новым: `tup = tup + (new_element,)`. Старый объект при этом останется прежним, а в переменную запишется новый.

**В: Когда лучше использовать кортеж вместо списка?**
**О:** 1) Когда данные не должны меняться в процессе программы (защита от ошибок). 2) Когда нужно использовать структуру как ключ в словаре. 3) Когда важна микро-оптимизация памяти и скорости.

# 📕 Шпаргалка: Словари (Dictionaries)

**Словарь (`dict`)** — это изменяемая, неупорядоченная (до Python 3.7) / упорядоченная по порядку вставки (с Python 3.7+) коллекция пар **«ключ: значение»**. Это, пожалуй, самая важная структура данных в Python.

### 🛠 1. Создание
```python
# Пустой словарь
d = {} 
d = dict()

# С начальными значениями
d = {'name': 'Alice', 'age': 2ert}
d = dict(name='Alice', age=25) # Через именованные аргументы (удобно, если ключи — строки)

# Из итерируемого объекта (списка кортежей)
pairs = [('a', 1), ('b', 2)]
d = dict(pairs)
```

### 🚀 2. Основные операции
*   **Добавление/Обновление:** `d['key'] = value` — если ключ есть, значение перезапишется; если нет — создастся новый.
*   **Доступ к значению:**
    *   `d['key']` — вернет значение, но **выбросит `KeyError`**, если ключа нет. (Опасно!)
    *   `d.get('key', default_value)` — вернет `default_value`, если ключа нет. Это **золотой стандарт** безопасного доступа.
*   **Удаление:**
    *   `del d['key']` — удаляет ключ, кидает ошибку, если его нет.
    *   `d.pop('key')` — удаляет ключ и **возвращает** его значение. Можно указать дефолт: `d.pop('key', None)`.
    *   `d.popitem()` — удаляет и возвращает последнюю добавленную пару (LIFO).
    *   `d.clear()` — полностью очищает словарь.

### 🔄 3. Итерация и методы представления
Словари возвращают не списки, а **view-объекты** (динамические представления). Если словарь изменится, view тоже обновится.
*   `d.keys()` — все ключи.
*   `d.values()` — все значения.
*   `d.items()` — пары `(ключ, значение)` в виде кортежей.

```python
for key, value in d.items():
    print(f"{key} -> {value}")
```

### ⚡️ 4. Dictionary Comprehensions (Генераторы словарей)
Мощный способ создания словарей «на лету».
```python
# Квадраты чисел от 0 до 4
squares = {x: x**2 for x in range(5)} 
# {'0': 0, '1': 1, '2': 4, '3': 9, '4': 16}

# С условием (только четные)
even_squares = {x: x**2 for x in range(10) if x % 2 == 0}
```

### ⚠️ 5. Нюансы и "Подводные камни" (Senior Level)

1.  **Требование к ключу (Hashability):** Ключом может быть только **hashable** объект. Это значит, что объект должен иметь неизменяемое состояние (immutable).
    *   ✅ `str`, `int`, `float`, `tuple` (если внутри него тоже hashable объекты), `frozenset`.
    *   ❌ `list`, `dict`, `set` — **нельзя** использовать как ключи.
2.ключ `1` и строка `'1'` — это разные ключи. Но `1.0` и `1` будут считаться одним и тем же ключом (так как `1 == 1.0` и их хеши совпадают).
3.  **Сложность операций:** Поиск, добавление и удаление в среднем работают за **$O(1)$**. Это делает словари невероятно быстрыми для задач поиска.
4.  **Порядок вставки:** Начиная с Python 3.7, словари гарантируют сохранение порядка добавления элементов. Но не полагайся на это в логике, которая должна работать на очень старых версиях (хотя сейчас это редкость).

---

### ❓ FAQ (Частые вопросы)

**В: В чем разница между `d['key']` и `d.get('key')`?**
**О:** `d['key']` — агрессивный метод. Если ключа нет, программа упадет с ошибкой. `d.get()` — вежливый метод. Он вернет `None` (или ваш дефолт), не прерывая выполнение программы. Всегда используй `.get()`, если не уверен на 100% в наличии ключа.

**В: Можно ли использовать список в качестве ключа?**
**О:** Нет. Список — изменяемый объект (`mutable`). Его хеш может измениться, что разрушит структуру хэш-таблицы словаря. Используй `tuple` вместо `list`.

**В: Что такое `defaultdict` из модуля `collections`?**
**О:** Это "умный" словарь. При обращении к несуществующему ключу он не выдает ошибку, а автоматически создает этот ключ с дефолтным значением (например, пустым списком или нулем). Очень полезно при группировке данных.

**В: Как объединить два словаря в один?**
**О:** 
*   Старый способ: `d1.update(d2)` (изменяет `d1` на месте).
*   Современный (Python 3.9+): `new_dict = d1 | d2` (оператор объединения, создает новый словарь).

# 🧠 Шпаргалка: Множества (Sets & Frozensets)

**Множество (set)** — это неупорядоченная коллекция **уникальных** и **хешируемых** элементов. Представь себе мешок с шарами: ты не можешь знать, в каком порядке они лежат, но точно знаешь, что двух одинаковых шаров там быть не может.

### 🛠 1. Создание и база
*   `my_set = {1, 2, 3}` — создание через фигурные скобки.
*   `empty_set = set()` — **ВНИМАНИЕ!** `empty_set = {}` создаст пустой **словарь (dict)**, а не множество. Это классическая ошибка новичков.
*   `from_list = set([1, 2, 2, 3])` $\rightarrow$ `{1, 2, 3}` — использование множества для удаления дубликатов из списка.

### ⚡️ 2. Ключевые свойства (Senior Insights)
1.  **Уникальность:** Множество автоматически игнорирует повторы.
2.  **Неупорядоченность:** В `set` нет индексов. Ты не можешь написать `my_set[0]`. Порядок элементов может меняться при добавлении новых.
3.  **Хешируемость (Hashability):** В множество можно положить только объекты, которые нельзя изменить (immutable). 
    *   ✅ Можно: `int`, `float`, `str`, `tuple`, `frozenset`.
    *   ❌ Нельзя: `list`, `dict`, `set` (они мутабельны и не имеют постоянного хеша).

### 🔧 3. Основные операции (Методы)
*   **Добавление:**
    *   `.add(x)` — добавить один элемент.
    *   `.update([x, y])` — добавить сразу несколько элементов (из списка, кортежа или другого множества).
*   **Удаление (Важный нюанс!):**
    *   `.remove(x)` — удаляет `x`. Если `x` нет в множестве $\rightarrow$ **выбросит ошибку `KeyError`**.
    *   `.discard(x)` — удаляет `x`. Если `x` нет $\rightarrow$ **ничего не произойдет**. (Используй это, если хочешь безопасного удаления).
    *   `.pop()` — удаляет и возвращает *случайный* элемент. Поскольку порядок не гарантирован, "случайность" здесь — это просто особенность внутренней реализации.
    *   `.clear()` — полностью очищает множество.

### 📐 4. Математические операции (Set Theory)
Это то, ради чего множества существуют. Они работают невероятно быстро ($O(1)$ для проверки наличия).

| Операция | Символ | Метод | Описание |
| :--- | :---: | :--- | :--- |
| **Объединение** | `\|` | `.union()` | Все элементы из обоих множеств. |
| **Пересечение** | `&` | `.intersection()` | Только те, что есть в обоих множествах. |
| **Разность** | `-` | `.difference()` | Элементы, которые есть в первом, но нет во втором. |
| **Симметричная разность** | `^` | `.symmetric_difference()` | Элементы, которые есть либо только в A, либо только в B (исключая общие). |

*Дополнительно:* Можно проверять подмножества: `a.issubset(b)` (является ли `a` частью `b`) или `a.issuperset(b)` (является ли `a` супермножеством для `b`).

### ❄️ 5. Frozenset (Замороженное множество)
`frozenset` — это тот же `set`, но **immutable** (неизменяемый).
*   Его нельзя дополнить или очистить после создания.
*   **Зачем он нужен?** Так как он неизменяем, он хешируем. Это значит, что `frozenset` можно использовать **как ключ в словаре** или **как элемент другого множества**.

---

### ❓ FAQ (Частые вопросы на собеседовании)

**Q: В чем разница между `remove()` и `discard()`?**
**A:** `remove()` вызывает исключение, если элемента нет. `discard()` — нет. В продакшн-коде, если ты не уверен в наличии элемента, используй `discard()`, чтобы избежать падения программы.

**Q: Какая сложность операций с множествами?**
**A:** Проверка наличия (`x in my_set`), добавление и удаление в среднем работают за **$O(1)$**. Это делает множества идеальными для задач, где нужно быстро проверять "был ли этот пользователь в списке черных?".

**Q: Можно ли положить список в множество?**
**A:** Нет. Список — это мутабельный объект. Его хеш может измениться при изменении самого списка, что разрушит структуру хеш-таблицы множества. Для этого используй `tuple`.

**Q: Когда использовать `set`, а когда `list`?**
**A:** 
1. Если нужны только уникальные элементы $\rightarrow$ `set`.
2. Если нужно проверять наличие элемента (`if x in collection`) на огромных данных $\rightarrow$ `set` (это в тысячи раз быстрее, чем в `list`).
3. Если важен порядок элементов и доступ по индексу $\rightarrow$ `list`.

# 🧠 Шпаргалка: Comprehensions (List, Dict, Set)

**Comprehensions** — это «синтаксический сахар», позволяющий создавать новые коллекции (списки, словари, множества) одной строкой на основе существующих итерируемых объектов. Это быстрее, короче и часто чище, чем обычный цикл `for` с методом `.append()`.

---

### 1. List Comprehension (Списки)
Самый частый гость в коде. Используется для трансформации или фильтрации элементов.

**Синтаксис:**
*   `[expression for item in iterable]` — Базовый вариант.
*   `[expression for item in iterable if condition]` — С фильтрацией.
*   `[expr_if_true if condition else expr_if_false for item in iterable]` — С тернарным оператором (важно: `if` переезжает в начало).

**Примеры:**
```python
nums = [1, 2, 3, 4, 5]

# 1. Просто возведение в квадрат
squares = [x**2 for x in nums] # [1, 4, 9, 16, 25]

# 2. Фильтрация (только четные)
evens = [x for x in nums if x % 2 == 0] # [2, 4]

# 3. С условием if-else (изменяем значение в зависимости от условия)
# Внимание: здесь 'if' стоит ПЕРЕД 'for'
labels = ["Even" if x % 2 == 0 else "Odd" for x/ in nums] 
# ['Odd', 'Even', 'Odd', 'Even', 'Odd']
```

---

### 2. Dict Comprehension (Словари)
Идеально для создания маппингов (ключ $\to$ значение) из списков или других словарей.

**Синтаксис:**
`{key_expression: value_expression for item in iterable if condition}`

**Примеры:**
```python
names = ["Alice", "Bob", "Charlie"]

# 1. Имя как ключ, длина как значение
name_lengths = {name: len(name) for name in names} 
# {'Alice': 5, 'Bob': 3, 'Charlie': 7}

# 2. Создание словаря из двух списков (используем zip)
keys = ['a', 'b', 'c']
values = [1, 2, 3]
d = {k: v for k, v in zip(keys, values)} 
# {'a': 1, 'b': 2, 'c': 3}
```

---

### 3. Set Comprehension (Множества)
Похож на List comprehension, но результат всегда содержит только **уникальные** элементы.

**Синтаксис:**
`{expression for item in iterable if condition}`

**Пример:**
```python
words = ["apple", "banana", "apple", "cherry", "banana"]

# Получаем набор уникальных первых букв слов
unique_starts = {w[0] for w in words} 
# {'a', 'b', 'c'}
```

---

### ⚠️ Senior Nuances (Нюансы и подводные камни)

1.  **Правило читаемости (The Readability Rule):** Если логика внутри comprehension становится слишком сложной (например, вложенные циклы или более одного `if-else`), **бросай это дело**. Обычный цикл `for` в таком случае лучше, потому что его легче дебажить и читать коллегам.
2.  **Side Effects (Побочные эффекты):** Никогда не используй comprehension для выполнения действий (например, `print()` или изменение глобальной переменной). Comprehension должен **только создавать** новую коллекцию. Если тебе нужно «пройтись и что-то сделать», используй обычный `for`.
3.  **Вложенные циклы:** Можно делать вложенные comprehension, но это "код-спагетти". 
    *   `[x for sublist in matrix for x in sublist]` — Это разворачивание матрицы (flattening). Порядок `for` здесь такой же, как в обычном вложенном цикле.
4.  **Generator Expressions (Бонус):** Если тебе не нужен весь список сразу в памяти, а нужно просто итерироваться по нему, используй круглые скобки: `(x**2 for x in range(1000000))`. Это **генератор**. Он не создает список в памяти, а вычисляет элементы "на лету". Это критически важно для больших данных.

---

### ❓ FAQ (Частые вопросы)

**В: Что быстрее: `list.append()` в цикле или List Comprehension?**
**О:** В большинстве случаев Comprehension работает быстрее, так как оптимизирован на уровне C-кода интерпретатора Python. Но разница заметна только на очень больших объемах данных.

**В: Можно ли использовать `if` и `else` одновременно в одном comprehension?**
**О:** Да, но синтаксис меняется. 
*   Если используешь **только** `if` (фильтрация) $\to$ он ставится в конце: `[x for x in items if x > 0]`.
*   Если используешь `if-else` (трансформация) $\to$ вся конструкция переносится в начало: `[x if x > 0 else 0 for x in items]`.

**В: Что будет, если в Set Comprehension попадутся дубликаты?**
**О:** Как и в обычном множестве (`set`), дубликаты будут автоматически отсеяны. На выходе останутся только уникальные значения.

# 🛠 Тема: Определение функций (Function Definition)

### 🧠 Суть
Функция — это именованный блок кода, который можно вызывать многократно. Это основной инструмент для соблюдения принципа **DRY** (*Don't Repeat Yourself*). Представь функцию как «черный ящик»: ты подаешь на вход данные (аргументы), внутри происходит магия, и на выходе ты получаешь результат (`return`).

### 📝 Синтаксис
```python
def имя_функции(параметры) -> тип_возвращаемого_значения:
    """Docstring: краткое описание того, что делает функция."""
    # Тело функции (логика)
    return результат  # Если нет return, функция вернет None
```

### 🚀 Виды аргументов и параметров
Чтобы писать гибкий код, нужно понимать все способы передачи данных:

1.  **Позиционные параметры:** Самые простые. Порядок важен.
2.  **Значения по умолчанию:** Позволяют вызывать функцию с меньшим количеством аргументов.
3.  **Именованные аргументы (Keyword arguments):** При вызове мы явно указываем имя параметра (`name="Alice"`), что делает код читаемым и позволяет игнорировать порядок.
4.  **`*args` (Variable positional arguments):** Собирает все «лишние» позиционные аргументы в один **кортеж (tuple)**.
5.    **`**kwargs` (Variable keyword arguments):** Собирает все «лишние» именованные аргументы в один **словарь (dict)**.

### 💻 Пример «всё в одном»
```python
def create_order(item: str, price: float, quantity: int = 1, *extras: str, **details) -> dict:
    """
    Создает структуру заказа.
    :param item: Название товара
    :param price: Цена за единицу
    :param quantity: Количество (по умолчанию 1)
    :param extras: Дополнительные опции (например, 'gift_wrap', 'fast_delivery')
    :param details: Метаданные (например, customer_id='123')
    """
    total = price * quantity
    order = {
        "item": item,
        "total_price": total,
        "extras": extras,  # Это будет tuple
        "metadata": details # Это будет dict
    }
    return order

# 1. Только обязательные аргументы
print(create_order("Apple", 50.0))

# 2. С именованным и позиционным аргументом + *args и **kwargs
print(create_append_order("Banana", 30.0, 2, "wrapped", "sticker", customer="John", priority="high"))
```

### ⚠️ Нюансы и «Подводные камни» (Senior Level)

1.  **🚨 ОПАСНО: Изменяемые объекты по умолчанию.**
    Никогда не используй `list`, `dict` или `set` в качестве значений по умолчанию. Python вычисляет значения аргументов **один раз** при определении функции, а не при каждом вызове.
    *   *Плохо:* `def add_item(item, my_list=[])` — список будет «жить» между вызовами и накапливать данные.
    *   *Хорошо:* `def add_item(item, my_list=None)` $\rightarrow$ внутри `if my_list is None: my_list = []`.

2.  **Type Hinting (Аннотации типов):** Всегда указывай типы. Это упрощает жизнь коллегам и IDE (PyCharm/VS Code), помогая ловить ошибки до запуска кода.

3.  **Порядок аргументов:** В определении функции строго соблюдай порядок: 
    `позиционные -> именованные с дефолтами -> *args -> **kwargs`. Нарушишь — получишь `SyntaxError`.

4.  **Чистые функции (Pure Functions):** Старайся, чтобы функция зависела только от своих аргументов и не меняла глобальные переменные. Это делает код тестируемым.

**О:** Параметр — это переменная, указанная в `def` (шаблон). Аргумент — это реальное значение, которое ты передаешь в функцию при вызове.

**В: Что будет, если функция не содержит `return`?**

# 🧠 Шпаргалка: Аргументы функций в Python

В программировании важно различать два термина: **Параметры** (переменные, которые мы указываем при объявлении функции) и **Аргументы** (реальные значения, которые мы передаем в функцию при её вызове).

### 1. Виды аргументов

#### 🔹 Позиционные аргументы (Positional Arguments)
Это самый простой тип. Значения передаются в функцию строго в том порядке, в котором объявлены параметры.
```python
def greet(name, age):
    print(f"Привет, {name}! Тебе {age} лет.")

greet("Алексей", 25)  # Порядок важен!
```

#### 🔹 Именованные аргументы (Keyword Arguments)
Позволяют передавать аргументы, явно указывая имя параметра. Это делает код читаемым и позволяет менять порядок.
```python
greet(age=25, name="Алексей")  # Порядок не важен, если есть имена
```

#### 🔹 Аргументы по умолчанию (Default Arguments)
Мы можем заранее задать значение параметру. Если аргумент не передан при вызове, возьмется значение «по умолчанию».
```python
def power(base, exp=2):
    return base ** exp

print(power(5))     # 25 (используется exp=2)
print(call(5, 3))   # 125 (перезаписали exp на 3)
```

#### 🔹 Произвольное количество аргументов (`*args` и `**kwargs`)
Используются, когда мы заранее не знаем, сколько данных придет в функцию.
*   **`*args`**: Собирает все лишние *позиционные* аргументы в **кортеж (tuple)**.
*   **`**kwargs`**: Собирает все лишние *именованные* аргументы в **словарь (dict)**.

```python
def super_func(*args, **kwargs):
    print(f"Args: {args}")   # Tuple
    print(f"Kwargs: {kwargs}") # Dict

super_func(1, 2, 3, name="Python", version=3.12)
```

### 2. Управление порядком (Advanced)

С версии Python 3.8+ мы можем жестко контролировать, как именно вызывается функция. Это критически важно при написании библиотек (API).

#### 🔹 Только позиционные аргументы (`/`)
Все, что стоит **до** знака `/`, можно передать *только* по позиции. Нельзя написать `name="Алексей"`.
```python
def pos_only(a, b, /):
    print(a, b)

pos_only(1, 2)     # OK
# pos_only(a=1, b=2) # ОШИБКА!
```

#### 🔹 Только именованные аргументы (`*`)
Все, что стоит **после** знака `*`, можно передать *только* по имени. Это заставляет разработчика писать читаемый код.
```python
def kw_only(*, name):
    print(name)

kw_only(name="Алексей") # OK
# kw_only("Алексей")    # ОШИБКА!
```

### ⚠️ Главный «подводный камень» (Senior Tip)
**Никогда не используй изменяемые типы (list, dict, set) в качестве значений по умолчанию!**

В Python значение по умолчанию вычисляется **один раз** при определении функции, а не при каждом её вызове. Это значит, что все вызовы функции будут делить один и тот же список.

```python
# ❌ ПЛОХО (Антипаттерн)
def add_item(item, my_list=[]):
    my_list.append(item)
    return my_list

print(add_item(1)) # [1]
print(add_item(2)) # [1, 2] — Ой! Список «запомнил» первый вызов!

# ✅ ХОРОШО
def add_item(item, my_list=None):
    if my_list is None:
        my_list = []
    my_list.append(item)
    return my_list
```

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: В каком порядке должны идти аргументы в `def func(...)`?**
**О:** Строго: Позиционные $\rightarrow$ Позиционные с дефолтами $\rightarrow$ `*args` $\rightarrow$ Именованные (keyword-only) $\rightarrow$ `**kwargs`.

**В: Чем отличается `*args` от распаковки списка при вызове функции?**
**О:** В определении функции `*args` — это **сборка** аргументов в кортеж. При вызове функции `func(*my_list)` — это **распаковка** элементов списка в отдельные позиционные аргументы.

**В: Что будет, если передать именованный аргумент, который уже есть в позиции?**
**О:** Python выбросит ошибку `TypeError: got multiple values for argument`. Это происходит, если вы сначала передали значение по позиции, а потом попытались переопределить его через имя.

**В: Зачем использовать `/` и `*` в сигнатуре функции?**
**О:** Для стабильности API. Если вы используете `/`, вы можете менять имена параметров в будущем, не ломая код пользователей (так как они привязаны к позиции). Если используете `*`, вы заставляете программиста писать явно `key=value`, что делает код самодокументированным.

# 🧠 Тема: Область видимости (Scope)

**Область видимости** — это зона в коде, где имя переменной считается «живым» и доступным для использования. Если ты пытаешься обратиться к переменной вне её зоны, Python выдаст `NameError`.

В Python поиск переменной происходит не хаотично, а по строгому правилу **LEGB**.

---

### 🛠 Правило LEGB (Порядок поиска)

Когда ты обращаешься к имени (например, `print(x)`), Python опрашивает уровни в следующем порядке:

1.  **L (Local) — Локальная область:** Переменные, объявленные внутри текущей функции. Как только функция завершается, эта область уничтожается.
2.  **E (Enclosing) — Замыкающая область:** Если у тебя есть «функция в функции», то переменные внешней функции для внутренней являются *enclosing*. Это критически важно для понимания замыканий.
3.  **G (Global) — Глобальная область:** Переменные, объявленные на уровне всего модуля (самого верхнего уровня файла). Доступны из любой функции в этом файле.
4.   **B (Built-in) — Встроенная область:** Самый глубокий уровень. Сюда входят все стандартные функции Python (`len`, `range`, `print`, `str` и т.д.). Если Python не нашел переменную ни в L, ни в E, ни в G, он проверяет, не является ли это встроенной функцией.

---

### 🗝 Ключевые слова: `global` и `nonlocal`

По умолчанию Python позволяет **читать** переменные из внешних областей, но **запрещает изменять** их (создавая при этом новую локальную переменную с тем же именем). Чтобы обойти это, нужны специальные инструкции.

#### 1. `global`
Используется, когда тебе нужно не просто прочитать, а **перезаписать** глобальную переменную внутри функции.
```python
x = 10 # Global

def change_global():
    global x 
    x = 20 # Теперь мы меняем именно ту x, что в глобальной области

change_global()
print(x) # Выведет 20
```

#### 2. `nonlocal`
Используется в «матрешках» (вложенных функциях). Он говорит: «Не ищи в глобальной области, ищи в ближайшей внешней функции».
```python
def outer():
    y = "original"
    
    def inner():
        nonlocal y
        y = "changed" # Меняем y из внешней (enclosing) функции
    
    inner()
s
print(y) # Выведет "changed"
```

### ⚠️ Нюансы и «Подводные камни» (Senior Tips)

1.  **Shadowing (Затенение):** Если ты назовешь локальную переменную так же, как глобальную, локальная переменная «затмит» глобальную. Глобальная всё еще существует, но внутри функции ты будешь работать с локальной. *Совет: избегай этого, чтобы не путать коллег.*
2.  **UnboundLocalError (Классическая ошибка):** Если ты попытаешься использовать переменную в функции и при этом где-то в этой же функции присвоишь ей значение, Python **сразу** пометит её как локальную. Если ты обратишься к ней *до* присваивания — будет ошибка.
    ```python
    x = 5
    def error_func():
        print(x) # ОШИБКА! Python видит присваивание ниже и считает x локальной
        x = 10   # Но здесь ты её создаешь локально
    ```
3.  **Мутация vs Перезапись:** Если глобальный объект — это список (`list`), ты можешь делать `.append()`, не используя `global`. Потомуy что ты не меняешь *имя* (ссылку), а меняешь *содержимое* объекта. Но если ты хочешь написать `x = [1, 2]`, то без `global` не обойтись.

### ❓ FAQ (Часто задаваемые вопросы)

**В: Можно ли внутри функции просто прочитать глобальную переменную?**
О: Да, Python позволяет читать значения из Global и Built-in областей без всяких ключевых слов. Ключевое слово нужно только для *изменения* (переприсваивания).

**В: В чем разница между `global` и `nonlocal`?**
О: `global` работает с уровнем модуля (самый верх файла). `nonlocal` работает с уровнем внешней функции в случае вложенности. `global` не видит переменные внутри функций, а `nonlocal` не лезет в глобальную область.

**В: Почему использование `global` считается плохой практикой?**
О: Это делает код непредсказуемым и трудным для тестирования. Функция становится зависимой от внешнего состояния мира. Если функция меняет глобальную переменную, её сложно изолировать и проверить — её результат зависит от того, что произошло в программе «до» неё.

**В: Что произойдет, если я назову свою функцию `len`?**
О: Произойдет Shadowing. Ты сможешь вызывать свою функцию `len()`, но стандартная встроенная функция станет недоступна внутри этой области видимости. Это приведет к катастрофе при попытке использовать `len([1,2])`.

# 🚀 Шпаргалка: Лямбда-функции (Lambda Functions)

### 🧠 Суть
**Лямбда-функция** — это «анонимная» функция. Она не имеет имени (в отличие от функций, созданных через `def`) и предназначена для выполнения коротких операций в одну строку. Её главная задача — быть временным инструментом, который нужен здесь и сейчас, чтобы не засорять пространство имен глобальными именами.

### 🛠 Синтаксис
```python
lambda аргументы: выражение
```
*   **`lambda`** — ключевое слово.
*   **аргументы** — любые параметры (как в обычной функции), через запятую.
*   **`:`** — разделитель.
*   **выражение** — единственная строка кода, результат которой **автоматически возвращается** (слово `return` писать нельзя!).

### 💻 Примеры использования

#### 1. Базовая математика
```python
# Обычная функция
def add(x, y): return x + y

# Лямбда-аналог
add_lambda = lambda x, y: x + y

print(add_lambda(5, 3)) # Вывод: 8
```

#### 2. Использование в `sorted()` (Самый частый кейс)
Лямбды незаменимы, когда нужно отсортировать список сложных объектов (например, кортежей или словарей) по конкретному ключу.
```python
users = [("Alice", 25), ("Bob", 19), ("Charlie", 30)]

# Сортируем по возрасту (второй элемент кортежа)
sorted_users = sorted(users, key=lambda user: user[1])

print(sorted_users) # [('Bob', 19), ('Alice', 25), ('Charlie', 30)]
```

#### 3. В связке с `filter()` и `map()`
```python
nums = [1, 2, 3, 4, 5, 6]

# Filter: оставляем только четные
evens = list(filter(lambda x: x % 2 == 0, nums)) # [2, 4, 6]

# Map: возводим в квадрат
squares = list(map(lambda x: x**2, nums)) # [1, 4, 9, 16, 25, 36]
```

### ⚠️ Нюансы и "Подводные камни" (Senior Tips)

1.  **Только одно выражение:** В лямбде нельзя использовать инструкции (statements), такие как `if` (в виде блока), `for`, `while`, `pass` или `assert`. Можно использовать только **тернарный оператор**: 
    *   ✅ `lambda x: "Even" if x % 2 == 0 else "Odd"`
    *   ❌ `lambda x: if x > 0: return x` (Ошибка!)
2.  **Читаемость превыше всего:** Если логика лямбды становится сложнее, чем простая проверка — **забудьте про лямбду**. Пишите обычную функцию через `def`. Код должен быть понятен коллегам через полгода. "Умный" код, который невозможно прочитать — плохой код.
3.  **Отсутствие имени:** Не присваивайте лямбдам имена (типа `my_func = lambda x: x`). Если вам нужно имя, используйте `def`. Лямбда должна быть «вброшена» прямо в аргумент другой функции.

---

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: В чем принципиальная разница между `def` и `lambda`?**
**О:** `def` создает именованную функцию, поддерживает многострочный код, инструкции (`if`, `for`) и имеет полноценную область видимости. `lambda` — это однострочное выражение, которое возвращает результат сразу, и она анонимна.

**В: Можно ли внутри лямбды использовать `return`?**
**О:** Нет. Лямбда по определению возвращает результат вычисления выражения, стоящего после двоеточия. Попытка написать `lambda x: return x` вызовет `SyntaxError`.

**В: Когда использование лямбды считается плохим тоном (Bad Practice)?**
**О:** Когда лямбда становится слишком длинной и сложной. Если внутри лямбды начинается «ад» из тернарных операторов, это признак того, что пора переходить на `def`. Также плохо использовать лямбды там, где можно использовать готовую функцию из стандартной библиотеки (например, вместо `lambda x: x.lower()` лучше написать `str.lower`).

# 🧠 Шпаргалка: Функции высшего порядка (Higher-Order Functions)

### 📌 Суть
В Python функции — это **«объекты первого класса»** (first-class citizens). Это значит, что функцию можно вести себя так же, как число или строку: записывать в переменную, передавать в другую функцию и возвращать из функции.

**Функция высшего порядка (ФВП)** — это функция, которая делает хотя бы одно из двух:
1. Принимает другую функцию как аргумент.
2. Возвракащает другую функцию как результат.

---

### 🛠 1. Функции как аргументы (Callbacks)
Это самый частый сценарий. Мы передаем «инструкцию» внутрь другой функции.

**Пример с `sorted()`:**
Функция `sorted` — это ФВП. Параметр `key` ожидает функцию, которая скажет, по какому признаку сортировать.

```python
names = ["Alice", "Bob", "Christopher", "Dan"]

# Передаем встроенную функцию len (длина строки) как правило сортировки
sorted_names = sorted(names, key=len) 
# Результат: ['Bob', 'Dan', 'Alice', 'Christopher']
```

**Пример с `map()` и `filter()`:**
*   `map(func, iterable)` — применяет `func` к каждому элементу.
*   `filter(func, iterable)` — оставляет только те элементы, где `func` вернула `True`.

```python
nums = [1, 2, 3, 4, 5]

# map: возводим в квадрат
squares = list(map(lambda x: x**2, nums)) # [1, 4, 9, 16, 25]

# filter: оставляем только четные
evens = list(filter(lambda x: x % 2 == 0, nums)) # [2, 4]
```

---

### 🏭 2. Функции, возвращающие функции (Factories)
Это фундамент для создания декораторов и фабрик объектов. Мы создаем «завод» по производству функций.

**Пример: Функция-генератор множителей**
```python
def make_multiplier(n):
    # Эта внутренняя функция "запоминает" значение n (это называется замыканием)
    def multiplier(x):
        return x * n
    return multiplier

double = make_multiplier(2) # Теперь double — это функция, которая умножает на 2
triple = make_multiplier(3) # А triple — на 3

print(double(10)) # 20
print(triple(10)) # 30
```

---

### ⚠️ Нюансы и "Подводные камни" (Senior Tips)

1.  **Передача функции vs Вызов функции:**
    *   `func` — передаем саму функцию (ссылку на неё). **Правильно для ФВП.**
    *   `func()` — вызываем функцию и передаем её *результат*. **Частая ошибка новичков.**
    *   *Пример:* `map(len, names)` ✅ vs `map(len(), names)` ❌ (выдаст ошибку, так как `len()` не имеет аргументов).

2.  **List Comprehensions vs `map`/`filter`:**
    В современном Python вместо `map` и `filter` чаще используют **List Comprehensions**. Они читаются легче и зачастую работают быстрее.
    *   *Senior style:* `[x**2 for x in nums if x % 2 == 0]` вместо `list(map(lambda x: x**2, filter(lambda x: x % 2 == 0, nums)))`. Используй `map/filter` только если это действительно упрощает логику или когда работаешь с очень большими итераторами (ленивые вычисления).

3.  **Lambda-ограничения:**
    Лямбда-функции — это анонимные функции в одну строку. Не пытайся запихнуть в них сложную логику. Если `lambda` занимает больше одной строки или содержит сложные условия — выноси её в обычный `def`. Чистый код важнее экономии строк.

---

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Чем функция высшего порядка отличается от обычной функции?**
**О:** Обычная функция работает с данными (числа, строки). Функция высшего порядка работает с *логикой* (другими функциями), позволяя абстрагировать поведение.

**В: Что такое замыкание (Closure) и как оно связано с ФВП?**
**О:** Замыкание — это случай, когда внутренняя функция «захватывает» переменные из внешней области видимости (как в примере с `make_multiplier`) и сохраняет их даже после того, как внешняя функция завершила работу. Это часто реализуется через ФВП.

**В: Где в реальной разработке мы встречаем ФВП?**
**О:** 
1. **Декораторы** (это чистая ФВП).
2. **Обработка событий** (callback-функции в GUI или асинхронном коде).
3. **Сортировка и фильтрация** сложных структур данных.
4. **Middleware** в веб-фреймворках (Django, FastAPI).

# 🧠 Шпаргалка: Замыкания (Closures)

### 🎯 Суть простыми словами
Представь, что функция — это путешественник. Когда функция рождается внутри другой функции, она не просто уходит в свободное плавание, а берет с собой «рюкзак» с вещами (переменными) из своего родного дома. 

**Замыкание** — это когда внутретеняя функция «запоминает» значения переменных из своей внешней области видимости, даже если внешняя функция уже закончила свою работу и завершилась.

---

### 🛠 Три обязательных условия
Чтобы возникло замыкание, должны соблюдаться три правила:
1.  Есть **вложенная функция** (функция внутри функции).
2.  Внешняя функция имеет **локальную переменную**.
3.  Внутренняя функция **использует** эту переменную.

---

### 💻 Синтаксис и пример
Классический пример — создание функции-множителя.

```python
def make_multiplier(factor):
    # Внешняя переменная 'factor' — это "содержимое рюкзака"
    def multiplier(number):
        return number * factor  # Мы используем factor здесь
    return multiplier

# Создаем две разные функции с разным "памятью"
times3 = make_multiplier(3)
times5 = make_multiplier(5)

print(times3(10)) # 30 (функция помнит, что factor был 3)
print(times5(10)) # 50 (функция помнит, что factor был 5)
```

---

### ⚠️ Нюансы и "подводные камни" (Senior Level)

#### 1. Ключевое слово `nonlocal` (Изменение состояния)
Если ты просто читаешь переменную — всё ок. Но если ты попытаешься **изменить** её внутри замыкания, Python решит, что ты создаешь новую локальную переменную, и замыкание сломается. Чтобы "достучаться" до переменной в рюкзаке и изменить её, нужно использовать `nonlocal`.

```python
def create_counter():
    count = 0
    def increment():
        nonlocal count  # Без этого будет ошибка UnboundLocalError
        count += 1
        return count
    return increment

counter = create_counter()
print(counter()) # 1
print(counter()) # 2
```

#### 2. Проблема "Late Binding" (Позднее связывание)
Это классическая ловушка в циклах. Замыкания ищут значение переменной в момент **вызова**, а не в момент создания.

*Ошибка:*
```python
funcs = []
for i in range(3):
    funcs.append(lambda: i)

# Мы ожидаем [0, 1, 2], но получим [2, 2, 2]
# Потому что к моменту вызова цикл завершился и 'i' равно 2 для всех функций.
print([f() for f in funcs]) 
```
*Решение:* Передавать текущее значение `i` как аргумент по умолчанию: `lambda x=i: x`.

#### 3. Память и `__closure__`
Замыкание — это не магия, а объект. Ты можешь заглянуть в «рюкзак» функции через атрибут `__closure__`. Там хранятся объекты типа `cell`, которые удерживают значения. Если ты захватил в замыкание огромный список, он будет висеть в памяти до тех пор, пока жива внутренняя функция.

---

### ❓ FAQ (Частые вопросы на собеседовании)

**В: Чем замыкание отличается от декоратора?**
**О:** Это разные вещи, но они связаны. Декоратор — это паттерн проектирования, а замыкание — это механизм, на котором декораторы работают. По сути, почти каждый декоратор использует замыкание, чтобы «запомнить» декорируемую функцию.

**В: Когда лучше использовать класс, а когда замыкание?**
**О:** Если тебе нужно просто хранить состояние и иметь один-два метода — используй **замыкание** (оно легче и быстрее). Если же у тебя много методов, сложная логика и нужно наследование — используй **класс**.

**В: Что такое область видимости LEGB?**
**О:** Это порядок, в котором Python ищет переменные: 
1. **L**ocal (внутри функции);
2. **E**nclosing (в замыкании/внешней функции);
3. **G**lobal (на уровне модуля);
4. **B**uilt-in (предопределенные в Python, например `len`). 
Замыкания работают именно на этапе **E**.

# 🐍 Шпаргалка: Декораторы (Decorators)

### 💡 Суть простыми словами
**Декоратор** — это «обертка» для функции. Представь, что у тебя есть подарок (функция). Ты можешь положить его в коробку, обклеить лентой и добавить открытку (декоратор), не меняя сам подарок внутри. 

С технической точки зрения: это функция, которая принимает другую функцию, добавляет ей новую логику и возвращает её обновленную версию.

### 🛠 Базовый синтаксис
В Python функции — это «объекты первого класса». Их можно передавать в другие функции как аргументы.

```python
def my_decorator(func):
    def wrapper():
        print("--- Логика ДО вызова ---")
        func()  # Вызов оригинальной функции
        print("--- Логика ПОСЛЕ вызова ---")
    return wrapper

@my_decorator
def say_hello():
    print("Привет, мир!")

say_hello()
```
*Запись `@my_decorator` — это просто «синтантаксический сахар». Это то же самое, что `say_hello = my_decorator(say_hello)`.*

---

### 🚀 Продвинутый уровень (То, что важно знать Senior-у)

#### 1. Универсальность: `*args` и `**kwargs`
Если ты напишешь декоратор только для функций без аргументов (как в примере выше), он сломается, как только ты попробукуешь декорировать функцию с параметрами. **Всегда** используй `*args` и `**kwargs`.

```python
def universal_decorator(func):
    def wrapper(*args, **kwargs):
        print("Подготовка...")
        result = func(*args, **kwargs) # Сохраняем результат выполнения!
        print("Завершение...")
        return result # Возвращаем результат оригинальной функции
    return wrapper
```

#### 2. Главная ошибка: Потеря метаданных (`functools.wraps`)
Когда ты оборачиваешь функцию, она «забывает» свое имя и документацию (docstring), так как теперь она — это `wrapper`. Это ломает отладку и автодокументацию. 
**Решение:** Всегда используй `@functools.wraps(func)`.

```python
from functools import wraps

def smart_decorator(func):
    @wraps(func) # Копирует имя, docstring и т.д. из func в wrapper
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper
```

#### 3. Декораторы с аргументами (Декоратор декоратора)
Иногда нужно передать настройки в сам декоратор (например, уровень логирования). Для этого создается «фабрика декораторов» — функция, которая возвращает декоратор.

```python
def repeat(times):
    def decorator(func):
        @wraps(func)
แปลง        def wrapper(*args, **kwargs):
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(times=3)
def greet():
    print("Привет!")
```

### 🎯 Зачем это нужно в реальной жизни? (Use Cases)
1.  **Logging (Логирование):** Записывать, когда и с какими аргументами вызывалась функция.
2.  **Timing (Профилирование):** Измерять время выполнения функции (полезно для поиска узких мест).
3.  **Authorization (Доступ):** Проверять, имеет ли пользователь права на выполнение действия (часто в Django/Flask).
4.  **Caching (Кэширование):** Сохранять результат тяжелых вычислений (`@functools.lru_cache`).
5.  **Retry (Повторы):** Автоматически перезапускать функцию, если она упала с ошибкой (например, при запросе к API).

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Что произойдет, если не использовать `return result` внутри `wrapper`?**
**О:** Функция, которую ты декорируешь, всегда будет возвращать `None`, даже если она должна была вернуть число или строку. Это классическая ошибка новичка.

**В: Можно ли вешать несколько декораторов на одну функцию?**
**О:** Да. Они применяются «снизу вверх» (как матрешка). Сначала применится тот, что ближе к функции, затем следующий.

**В: В чем разница между декоратором и функцией-оберткой?**
**О:** Декоратор — это инструмент для автоматизации применения обертки. Он позволяет не писать вызов обертки вручную каждый раз, а использовать лаконичный синтаксис `@`.

**В: Как работает `functools.wraps` под капотом?**
**О:** Он копирует атрибуты объекта функции (например, `__name__`, `__doc__`, `__annotations__`) из оригинальной функции в новую функцию-обертку. Без него `help(my_func)` покажет информацию о `wrapper`.

# 🧱 Классы и Объекты (Classes & Objects)

### 💡 Суть простыми словами
Представь, что **Класс** — это чертеж автомобиля. На чертеже указано, что у машины должны быть колеса, руль и двигатель, и она должна уметь ехать. Но на чертеже нельзя поехать в магазин.

**Объект (Экземпляр)** — это реальный автомобиль, собранный по этому чертежу. У него есть конкретный цвет, номерной знак, и он физически существует в памяти компьютера. Ты можешь создать 100 разных машин (объектов) по одному чертежу (классу).

---

### 🛠 Основные компоненты

1.  **`class Name:`** — объявление чертежа. Имена классов всегда пишутся с большой буквы (`PascalCase`).
2.  **`__init__(self, ...)`** — **Конструктор** (точнее, инициализатор). Это метод, который запускается автоматически в момент создания объекта. Здесь мы задаем начальные свойства (атрибуты).
3.  **`self`** — это ссылка на *текущий* конкретный объект. Через `self` объект понимает, что «это именно мои колеса, а не чьи-то еще». 
    > *Важно: `self` — это не зарезервированное слово Python, но стандарт индустрии. Никогда не называй его иначе.*
4.  **Атрибуты** — переменные внутри класса (характеристики).
5.  **Методы** — функции внутри класса (поведение).

---

### 💻 Пример кода

```python
class Car:
    # Атрибут класса (общий для всех машин)
    wheels = 4 

    def __init__(self, brand, model, color):
        # Атрибуты экземпляра (у каждой машины свои)
        self.brand = brand
        self.model = model
        self.color = color
        self.speed = 0

    # Метод экземпляра
    def accelerate(self, increment):
        self.speed += increment
        print(f"🚗 {self.brand} {self.model} разогнался до {self.speed} км/ч")

    # Метод класса (работает с самим классом, а не с объектом)
    @classmethod
    def change_wheels_count(self, new_count):
        Car.wheels = new_count

    # Статический метод (просто функция внутри класса для порядка)
    @staticmethod
    def is_motorized(vehicle_type):
        return vehicle_type in ["car", "truck", "bike"]

# --- Использование ---

# Создаем объекты (экземпляры)
my_car = Car("Tesla", "Model 3", "Red")
your_car = Car("BMW", "M5", "Black")

print(mys_car.brand)  # Tesla
my_car.accelerate(50) # 🚗 Tesla Model 3 разогнался до 50 км/ч

# Проверка атрибута класса
print(your_car.wheels) # 4
```

---

### ⚠️ Нюансы и «Подводные камни» (Senior Tips)

1.  **Атрибуты класса vs Атрибуты экземпляра**: 
    Если ты изменишь `Car.wheels = 3`, то у **всех** созданных и будущих машин станет 3 колеса. Если ты изменишь `my_car.wheels = 3`, то изменится только у одной машины (Python создаст локальный атрибут для этого объекта).
    
2.  **Мутабельные аргументы в `__init__`**: 
    **Никогда** не используй изменяемые типы (списки, словари) как значения по умолчанию в аргументах.
    *Плохо:* `def __init__(self, items=[])` — список `items` будет общим для всех объектов, созданных без этого аргумента!
    *Хорошо:* `def __init__(self, items=None): self.items = items or []`.

3.  **Инкапсуляция (Приватность)**: 
    В Python нет жесткого запрета на доступ к данным, но есть соглашения:
    *   `_name` (одно подчеркивание) — «Пожалуйста, не трогай это вне класса» (protected).
    *   `__name` (два подчеркивания) — Включает *name mangling*, чтобы случайно не перезаписать атрибут в подклассах (private).

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Чем `self` отличается от обычного аргумента функции?**
О: `self` позволяет методу обращаться к данным конкретного объекта. Без него метод не будет знать, чью именно скорость (`speed`) нужно увеличивать.

**В: В чем разница между `@classmethod` и `@staticmethod`?**
О: `@classmethod` принимает первым аргументом сам класс (`cls`) и может менять атрибуты класса. `@staticmethod` не знает ни о классе, ни об объекте — это просто логически связанная функция, которая живет внутри пространства имен класса.

**В: Что такое `__init__`? Это конструктор?**
О: Технически, конструктор — это метод `__new__`, который *создает* объект. А `__init__` — это инициализатор, который *настраивает* уже созданный объект. Но в 99% случаев на собеседованиях можно говорить, что это конструктор.

**В: Как сделать атрибут «неизменяемым»?**
О: В Python нет констант в строгом смысле. Можно использовать `@property` (геттеры), чтобы возвращать значение, но не давать его перезаписывать через сеттер.
</p>

Магические методы (или **Dunder methods**, от *Double Underscore*) — это «крючки» (hooks), которые позволяют твоим объектам взаимодействовать с синтаксисом Python так же, как это делают встроенные типы (списки, числа, строки). Без них твой класс — это просто набор данных. С ними — полноценный участник экосистемы языка.

# 🪄 Магические методы (Dunder Methods)

### 1. Жизненный цикл объекта (Lifecycle)
Эти методы управляют созданием и уничтожением экземпляра.

*   `__new__(cls, ...)` — **Самый важный нюанс.** Это настоящий конструктор. Он *создает* объект и возвращает его. Используется редко (например, в паттерне Singleton или при наследовании от неизменяемых типов вроде `str` или `int`).
*   `__init__(self, ...)` — Инициализатор. Он не создает объект, а лишь *настраивает* уже созданный.
*   `__del__(self)` — Деструктор. Вызывается при удалении объекта сборщиком мусора. *Осторожно: использование `__del__` может мешать работе Garbage Collector.*

### 2. Строковое представление (Representation)
Как твой объект «выглядит» в консоли и логах.

*   `__str__(self)` — Для пользователей. Должен быть красивым, читаемым и понятным. Вызывается `print()` и `str()`.
*   `__repr__(self)` — Для разработчиков. Должен быть максимально информативным (в идеале — таким кодом, который можно скопировать и вызвать `eval()` для воссоздания объекта). Вызывается при просмотре в консоли или через `repr()`.

> **Senior Tip:** Если ты определил только `__repr__`, то `__str__` будет использовать его как фолбек. Всегда определяй хотя бы `__repr__`.

### 3. Математические операции (Operator Overloading)
Позволяют складывать, вычитать и сравнивать объекты через стандартные символы (`+`, `-`, `*`, `/`).

*   **Арифметика:** `__add__` (+), `__sub__` (-), `__mul__` (*), `len__truediv__` (/).
*   **Сравнение:** `__eq__` (==), `__ne__` (!=), `__lt__` (<), `__le__` (<=), `__gt__` (>), `__ge__` (>=).

> **Senior Tip:** Не делай из `+` операцию удаления. Это называется "нарушением принципа наименьшего удивления" (Principle of Least Astonishment). Если ты перегружаешь методы, веди себя предсказуемо.

### 4. Работа с контейнерами (Sequence/Mapping)
Превращают твой объект в некое подобие списка или словаря.

*   `__len__(self)` — Позволяет использовать `len(obj)`.
*   `__getitem__(self, key)` — Реализует доступ по индексу: `obj[key]`.
*   __setitem__(self, key, value) — Позволяет изменять значение по индексу: `obj[key] = val`.
*   `__contains__(self, item)` — Реализует оператор `in`.
*   `__iter__(self)` — Делает объект итерируемым (позволяет использовать в `for x in obj`).

### 5. Доступ к атрибутам и вызов (Attribute & Callable)
Управление «магией» внутри объекта.

*   `__call__(self, ...)` — Позволяет вызывать объект как функцию: `obj()`.
*   `__getattr__(self, name)` — Вызывается, **только если** атрибут *не найден*. Отличное место для динамических свойств.
*   `__getattribute__(self, name)` — Вызывается **всегда** при любом обращении к атрибуту. 
    *   ⚠️ **Danger Zone:** Если внутри `__getattribute__` ты забудешь обработать рекурсию, программа упадет с `RecursionError`.

---

### 🛠 Пример кода: Создаем "Умный Список"

```python
class SmartList:
    def __init__(self, items):
        self.items = items

    # Представление для разработчика
    def __repr__(self):
        return f"SmartList({self.items})"

    # Сложение списков через +
    def __add__(self, other):
        if isinstance(other, SmartList):
            return SmartList(self.items + other.items)
        return NotImplemented

    # Доступ по индексу
    def __getitem__(self, index):
        return self.items[index]

    # Проверка наличия элемента через 'in'
    def __contains__(self, item):
        return item in self.items

# Тестируем
list1 = SmartList([1, 2])
list2 = SmartList([3, 4])

print(list1 + list2)  # Вывод: SmartList([1, 2, 3, 4]) -> Сработал __add__
print(2 in list1)     # Вывод: True               -> Сработал __contains__
print(list1[0])       # Вывод: 1                 -> Сработал __getitem__
```

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: В чем разница между `__str__` и `__repr__`?**
**О:** `__str__` — это "красивая обертка" для конечного пользователя. `__repr__` — это техническое описание объекта для отладки, которое должно быть однозначным.

**В: В чем разница между `__new__` и `__init__`?**
**О:** `__new__` — это статический метод, который создает объект (возвращает экземпляр класса). `__init__` — это метод экземпляра, который наполняет созданный объект данными.

**В: Что будет, если я перегружу `__eq__`, но не перегружу `__lt__`?**
**О:** Ты сможешь сравнивать объекты на равенство (`==`), но встроенная функция `sort()` или `sorted()` упадет с ошибкой, так как для сортировки Python нужно знать, какой объект "меньше" другого.

**В: Чем `__getattr__` отличается от `__getattribute__`?**
**О:** `__getattr__` — это «запасной план» (вызывается только при отсутствии атрибута). `__getattribute__` — это «контрольно-пропускной пункт» (вызывается при каждом обращении, даже если атрибут существует). Использование `__getattribute__` крайне опасно из-за риска бесконечной рекурсии.

# 🛡️ Инкапсуляция (Encapsulation)

**Суть простыми словами:**
Представь себе кофейный автомат. У него есть интерфейс: кнопки «Эспрессо», «Латте» и т.д. Тебе не нужно знать, какое давление в бойлере и как именно вращаются жернова кофемолки. Всё сложное скрыто внутри корпуса. Ты взаимодействуешь только с кнопками. 

**Инкапсуляция в коде** — это объединение данных (атрибутов) и методов для работы с ними в одном «корпусе» (классе) и ограничение прямого доступа к внутренним деталям этого класса, чтобы никто случайно не сломал логику программы.

---

### 🛠️ Уровни доступа в Python

В отличие от строгого Java, где есть ключевые слова `private` и `protected`, в Python всё строится на **соглашении между программистами**. Мы «все взрослые люди» (консенсус Python-сообщества), поэтому мы не запрещаем доступ физически, а договариваемся его не использовать.

#### 1. Public (Публичный)
Доступен отовсюду: внутри класса, в наследниках и снаружи.
*   **Синтаксис:** `self.name = "Python"`
*   **Зачем:** Для данных, которые не несут критической логики и могут свободно читаться/меняться.

#### 2. Protected (Защищенный) — *Условный*
Это «джентльменское соглашение». Мы ставим один символ подчеркивания `_`, говоря коллегам: *"Пожалуйста, не трогай это вне класса или его наследников, это внутренняя кухня"*. Но Python **не запрещает** доступ.
*   **Синтаксис:** `self._internal_id = 123`
*   **Зачем:** Чтобы пометить методы/атрибуты, которые важны для логики наследования, но не предназначены для конечного пользователя класса.

#### кредитная карта (Приватный) — *Маскировка*
Если поставить два подчеркивания `__`, Python применит механизм **Name Mangling** (искажение имен). Он переименует атрибут так, чтобы его было сложнее вызвать случайно извне.
*   **Синтаксис:** `self.__secret_key = "12345"`
*   **Как это работает:** Внутри Python превратит `__secret_key` в `_ClassName__secret_key`.
*   **Зачем:** Защита от случайного перезаписывания атрибута в подклассах (наследниках).

---

### 🚀 Правильный способ управления данными: `@property`

Просто менять атрибуты напрямую — плохая практика. Если завтра тебе понадобится добавить проверку (например, чтобы возраст не был отрицательным), тебе придется переписывать весь проект. 

**Pythonic Way** — использовать декоратор `@property`. Это позволяет обращаться к методу как к обычному атрибуту, но при этом запускать логику проверки.

```python
class User:
    def __init__(self, age):
        self._age = age  # Используем protected

    @property
    def age(self):
        """Геттер: позволяет читать значение"""
        print("Вы запрашиваете возраст...")
        return self._age

    @age.setter
    def age(self, value):
        """Сеттер: позволяет записывать с валидацией"""
        if value < 0:
            raise ValueError("Возраст не может быть отрицательным!")
        print(f"Устанавливаем возраст: {value}")
        self._age = value

# Использование
user = User(25)
print(user.age)  # Вызов геттера (как обычное поле)
user.age = 30    # Вызов сеттера
# user.age = -5  # Выбросит ошибку ValueError!
```

---

### ⚠️ Нюансы и «подводные камни»

1.  **Иллюзия приватности:** Помни, что `__private` — это не стена, а забор с надписью «Не входить». Любой Senior может достучаться до него через `_ClassName__attribute`. Не полагайся на это как на криптографическую защиту.
2.  **Не переусердствуй:** Если ты сделаешь всё приватным, твой класс станет неудобным для использования и тестирования. Делай приватным только то, что действительно может сломать внутреннюю логику при изменении.
3.  **Принцип единственной ответственности:** Инкапсуляция должна помогать скрывать сложность, а не превращать класс в «черный ящик», где невозможно понять, как работает даже простая операция.

**О:** Да, абсолютно. В Python нет жестких ограничений на уровне языка для защиты памяти (как в C++). Инкапсуляция здесь — это инструмент проектирования и чистоты кода, а не механизм безопасности.

# 🧬 Наследование (Inheritance)

**Суть:** Это механизм, позволяющий создать новый класс на основе уже существующего. Новый класс (наследник/subclass) забирает себе все атрибуты и методы родительского класса (базового класса/superclass). 

Это главный инструмент для соблюдения принципа **DRY** (*Don't Repeat Yourself* — не повторяйся). Вместо того чтобы копировать код, мы выносим общую логику в родителя.

### 🛠 Базовая механика

```python
class Animal:  # Родительский класс
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} издает звук")

class Dog(Animal):  # Наследник
    def speak(self):  # Переопределение метода (Overriding)
        print(f"{self.name} лает: Гав-гав!")

dog = Dog("Шарик")
dog.speak()  # Выведет: Шарик лает: Гав-гав!
```

---

### 🚀 Продвинутые концепции и нюансы

#### 1. Переопределение (Overriding) и `super()`
Часто нам не нужно полностью заменять метод родителя, а хочется **дополнить** его. Для этого используется функция `super()`. Она позволяет вызвать метод родительского класса, чтобы не переписывать его логику заново.

```python
class Bird(Animal):
    def __int__(self, name, can_fly=True):
        super().__init__(name)  # Вызываем конструктор родителя
        self.can_fly = can_fly
```

#### 2. Виды наследования
*   **Одиночное:** Один потомок $\rightarrow$ один предок (самый безопасный вариант).
*   **Многоуровневое:** Дедушка $\rightarrow$ Отец $\rightarrow$ Сын. Каждый следующий уровень имеет доступ ко всем уровням выше.
*   **Множественное:** Один потомок $\rightarrow$ несколько предков. Python позволяет это, но тут кроется главная опасность.

#### 3. MRO (Method Resolution Order) — Порядок поиска методов
Когда у тебя множественное наследование, возникает вопрос: *«Если метод `speak()` есть и в родителе А, и в родителе Б, чей метод вызовет Python?»*.

Python использует алгоритм **C3 Linearization** для построения цепочки **MRO**. Ты можешь посмотреть этот порядок через атрибут `__mro__`.
*   **Senior Tip:** Всегда помни, что поиск идет слева направо и снизу вверх по дереву наследования.

#### 4. Ловушка: Наследование vs Композиция (Composition)
Это то, на чем валятся джуны. 
*   **Наследование** — это связь **"is-a"** (является). *Собака — это Животное.*
*   **Композиция** — это связь **"has-a"** (содержит в себе). *У Машины есть Двигатель.*

**Золотое правило:** Если ты не можешь уверенно сказать "Класс Б является классом А", не используй наследование. Используй композицию (вложи один объект в другой). Глубокие иерархии наследования делают код хрупким и нечитаемым.

### ❓ FAQ (Частые вопросы на собеседовании)

**В: Чем `isinstance(obj, Class)` отличается от `issubclass(Class1, Class2)`?**
**О:** `isinstance` проверяет, является ли конкретный **объект** экземпляром класса или его наследником. `issubclass` проверяет, является ли один **класс** подклассом другого.

**В: Что делает `super()` на самом деле?**
**О:** Он не просто "вызывает родителя". Он возвращает объект, который делегирует вызов следующему классу в цепочке MRO. В сложном множественном наследовании это критически важно для правильного обхода всех предков.

**В: Можно ли запретить наследование класса?**
**О:** В чистом Python — нет (в отличие от Java или C#). Но можно использовать модуль `typing` и логику внутри `__init__`, либо просто следовать соглашению о приватности, хотя архитектурно это решается проектированием.

**В: Почему множественное наследование считается опасным?**
**О:** Оно может привести к "проблеме ромба" (Diamond Problem), когда один и тот же базовый класс имеет два разных пути к наследнику, что создает путаницу в том, какая версия метода должна быть вызвана. Хотя MRO в Python решает это, сложность отладки кода резко возрастает.

# 🧩 Полиморфизм в Python

**Полиморфизм** (от греч. *poly* — много, *morph* — форма) — это способность объектов с разным типом данных выполнять один и тот же интерфейс (метод), но каждый по-своему. 

Если упростить: ты даешь одну и ту же команду («Голос!»), но собака лает, а кошка мяукает. Тебе не нужно знать, кто перед тобой, тебе важно, что у объекта есть метод `.speak()`.

В Python полиморфизм проявляется в трёх основных видах:

### 1. Переопределение методов (Method Overriding)
Это классический подход из учебников ООП. Мы создаем иерархию классов, где дочерний класс меняет реализацию метода родителя.

```python
class Animal:
    def speak(self,):
        raise NotImplementedError("Subclass must implement this method")

class Dog(Animal):
    def speak(self):
        return "Woof!"

class Cat(Animal):
    def speak(self):
        return "Meow!"

# Полиморфизм в действии:
animals = [Dog(), Cat()]
for animal in animals:
    print(animal.speak())  # Мы вызываем один метод, но получаем разный результат
```

### 2. Утиная типизация (Duck Typing) — «Сердце Python»
Это самая важная концепция для Python-разработчика. В Python нам не важно, от какого класса унаследован объект. Нам важно только, **есть ли у него нужный метод**.

> *"Если это выглядит как утка, плавает как утка и крякает как утка, то это утка".*

```python
class Car:
    def move(self):
        return "Driving on roads"

class Boat:
    def move(self):
        return "Sailing on water"

# Функции плевать на типы, ей важен метод .move()
def start_journey(vehicle):
    print(func_result := vehicle.move())

start_journey(Car())   # Работает
start_journey(Boat())  # Тоже работает!
```

### 3. Перегрузка операторов (Operator Overloading)
Полиморфизм позволяет одному и тому же оператору (`+`, `*`, `==`) работать по-разному для разных типов данных. Это достигается через «магические» методы (dunder methods).

```python
print(1 + 2)           # Числа: математическое сложение (3)
print("Py" + "thon")   # Строки: конкатенация ("Python")
print([1] + [2])       # Списки: слияние списков ([1, 2])
```
*Как это работает:* Когда ты пишешь `a + b`, Python внутри вызывает `a.__add__(b)`.

---

### ⚠️ Нюансы и «подводные камни» (Senior Level)

1.  **Отсутствие классической перегрузки методов (Method Overloading):** В Java или C++ можно создать два метода с одним именем, но разными аргументами. **В Python так нельзя.** Если ты определишь два метода `def func(self, x)` и `def func(self, x, y)`, второй просто перезапишет первый. Чтобы имитировать перегрузку, используй значения по умолчанию (`args=None`) или `*args`.
2.  **Принцип подстановки Барбары Лисков (LSP):** Это часть SOLID. Полиморфизм не должен ломать логику. Если твой класс `Square` наследует `Rectangle`, но при изменении ширины меняет и высоту — ты нарушаешь полиморфизм, так как клиент ожидает поведения «прямоугольника», а получает «квадрат».
3.  **Опасность Duck Typing:** Поскольку Python не проверяет типы на этапе написания кода, ты можешь передать объект, у которого нет нужного метода, и получишь `AttributeError` уже во время выполнения (runtime). Для защиты используй **Abstract Base Classes (ABC)** или **Type Hinting**.

### ❓ FAQ (Частые вопросы на собеседовании)

**В: Чем Polymorphism отличается от Inheritance (Наследование)?**
**О:** Наследование — это про *структуру* (как классы связаны друг с другом), а полиморфизм — про *поведение* (как разные объекты реагируют на одну команду). Наследование часто является инструментом для достижения полиморфизма.

**В: Что такое Duck Typing и почему он крутой?**
**О:** Он делает код гибким и лаконичным. Тебе не нужно писать огромные проверки `if isinstance(obj, Dog)`. Ты просто полагаешься на наличие интерфейса, что позволяет легко подменять реализации (например, заменить реальную базу данных на Mock-объект в тестах).

**В: Как сделать полиморфизм более безопасным?**
**О:** Использовать модуль `abc` (Abstract Base Classes). Создавая абстрактный класс, ты гарантируешь, что любой подкласс *обязан* реализовать определенные методы, иначе программа не даст создать экземпляр этого класса.

**В: Можно ли реализовать полиморфизм без наследования?**
**О:** Да, именно через Duck Typing. Объекты могут быть вообще не связаны иерархией классов, но если у них совпадают имена методов — они полиморфны.

# 🧩 Тема: Абстракция (Abstraction)

### 💡 Суть простыми словами
**Абстракция** — это процесс скрытия сложных деталей реализации и выделения только самых важных характеристик объекта. 

Представь, что ты водитель автомобиля. Тебе не нужно знать, как работает цикл сгорания топлива или как давление масла влияет на поршни. Тебе достаточно интерфейса: руль, педали, рычаг передач. **Руль — это абстракция.** Ты нажимаешь на него (вызываешь метод), и машина поворачивает (результат достигается), а что происходит внутри — твоих забот не касается.

В программировании абстракция позволяет нам работать с объектами, не вникая в их внутреннюю «кухню», опираясь только на их публичный интерфейс.

---

### 🛠 Инструменты реализации в Python

В Python абстракция реализуется тремя основными способами: от концептуального (Duck Typing) до строгого (ABC).

#### 1. Abstract Base Classes (ABC) — «Строгий контракт»
Это самый формальный способ. Мы используем модуль `abc`, чтобы создать класс, который нельзя создать напрямую, а можно использовать только как шаблон для других классов.

**Зачем:** Чтобы гарантировать, что все подклассы реализуют определенные методы. Если разработчик забудет реализовать метод — Python выдаст ошибку еще на этапе создания объекта.

```python
from abc import ABC, abstractmethod

# Это абстрактный класс. Мы не можем создать "Shape" напрямую.
class Shape(ABC):
    @abstractmethod
    def area(self) -> float:
        """Метод для вычисления площади. Должен быть реализован в подклассах."""
        pass

    @abstractmethod
    def perimeter(self) -> float:
        pass

class Square(Shape):
    def __init__(self, side: float):
        self.side = side

    def area(self) -> float:
        return self.side ** 2

    def perimeter(self) -> float:
        return 4 * self.side

# shape = Shape()  # ОШИБКА! TypeError: Can't instantiate abstract class Shape
sq = Square(5)     # Работает отлично
print(sq.area())   # 25
```

#### 2. Duck Typing — «Утиная типизация» (Pythonic way)
Это более гибкий, «неформальный» подход. Принцип гласит: *«Если это выглядит как утка, плавает как утка и крякает как утка, то это и есть утка»*.

Нам не важно, от какого класса унаследован объект. Нам важно только, **есть ли у него нужный метод**.

```python
class Duck:
    def quack(self):
        print("Кря-кря!")

class Person:
    def quack(self):
        print("Я имитирую утку: Кря!")

def make_it_quack(obj):
    # Нам плевать, кто это (Duck или Person), лишь бы был метод quack()
    obj.quack()

make_it_quack(Duck())   # Работает
make_it_quack(Person()) # Тоже работает! Это и есть абстракция через интерфейс.
```

#### 3. Protocols (Structural Subtyping) — «Современный стандарт»
Появились в Python 3.8 (`typing.Protocol`). Это «золотая середина». В отличие от Duck Typing, здесь мы можем использовать статические анализаторы (например, `mypy`), чтобы проверить, соответствует ли объект протоколу, не прибегая к явному наследованию.

```python
from typing import Protocol

class Flyer(Protocol):
    def fly(self) -> None:
        ...

class Bird:
    def fly(self) -> None:
        print("Птица летит")

class Airplane:
    def fly(self) -> None:
        print("Самолет летит")

def lift_off(entity: Flyer):
    entity.fly()

lift_off(Bird())     # OK
lift_off(Airplane()) # OK, хотя Airplane не наследовался от Flyer явно!
```

---

### ⚠️ Нюансы и подводные камни (Senior Tips)

1.  **Абстракция vs Инкапсуляция:** Не путай их. *Инкапсуляция* — это «спрятать данные внутри (private)», а *Абстракция* — это «создать упрощенный интерфейс для взаимодействия».
2.  **Перебор с ABC:** Не делай всё абстрактным. Если ты создаешь слишком много уровней абстракции там, где достаточно простого класса, код станет "переусложненным" (overengineered) и его будет трудно читать.
3.  **Абстрактные методы могут иметь тело:** В Python `@abstractmethod` может содержать логику. Подклассы обязаны переопределить метод, но они могут вызывать `super().method()` для использования базовой реализации. Это полезно для уменьшения дублирования кода.
4.  **Ошибка инициализации:** Самая частая ошибка — попытка создать экземпляр абстрактного класса. Всегда помни: ABC — это только чертеж, а не готовое здание.

---

### ❓ FAQ (Часто задаваемые вопросы)

**В: Чем `Protocol` лучше обычного `Duck Typing`?**
**О:** `Duck Typing` работает только в рантайме (когда программа уже запущена). Если ты передашь не тот объект, ошибка вылетит в процессе работы. `Protocol` позволяет инструментам вроде PyCharm или Mypy подсветить ошибку еще *до* запуска кода.

**В: Можно ли реализовать абстрактный метод в дочернем классе, но оставить его абстрактным?**
**О:** Да, если ты не реализуешь *все* методы, помеченные `@abstractmethod`, класс всё равно останется абстрактным и его нельзя будет создать.

**В: Зачем использовать `ABC`, если есть `Protocol`?**
**О:** Используй `ABC`, когда тебе нужно **наследование** (передача общей логики через общие методы). Используй `Protocol`, когда тебе важен только **интерфейс** (наличие определенных методов) и ты не хочешь связывать классы жесткой иерархией.

# 🧠 Шпаргалка: Свойства (Properties)

### 💡 Суть
**Свойства (`@property`)** — это способ превратить метод класса в атрибут. Это «синтаксический сахар», который позволяет обращаться к методу так, будто это обычная переменная (без скобок `()`), но при этом запускать внутри скрытую логику: проверку данных, вычисления или логирование.

В Python мы используем свойства для реализации **инкапентсуляции** (скрытия внутренней реализации) и управления доступом к данным.

---

### 🛠 Синтаксис
Для создания полноценного свойства тебе понадобятся три декоратора:
1. `@property` — **Getter** (чтение). Позволяет получить значение.
2. `@<name>.setter` — **Setter** (запись). Позволяет изменить значение с проверкой.
3. `@<name>.deleter` — **Deleter** (удаление). Позволяет обработать удаление атрибута.

---

### 💻 Пример кода
Представь, что мы создаем класс `User`. Нам нужно, чтобы возраст нельзя было установить отрицательным.

```python
class User:
    def __init__(self, name, age):
        self.name = name
        # Мы используем внутренний атрибут _age (с нижним подчеркиванием)
        self._age = age 

    @property
    def age(self):
        """Getter: возвращает значение"""
        print(" world! Вы запросили возраст.")
        return self._age

    @age.setter
    def age(self, value):
        """Setter: проверяет данные перед записью"""
        if value < 0:
            raise ValueError("Возраст не может быть отрицательным!")
        print(f"Устанавливаем возраст: {value}")
        self._age = value

    @age.deleter
    def age(self):
        """Deleter: логика при удалении атрибута"""
        print("Удаляем данные о возрасте...")
        del self._age

# --- Использование ---
user = User("Alex", 25)

print(user.age)      # Вызов Getter (без скобок!) -> 2ществует 25
user.age = 30        # Вызов Setter -> Успешно
# user.age = -5      # Вызовет ValueError!

del user.age         # Вызов Deleter
```

---

### ⚠️ Нюансы (Senior Tips)

1.  **Конвенция нижнего подчеркивания (`_`)**: Всегда храни реальное значение в «защищенном» атрибуте (например, `self._age`). Если ты назовешь свойство и внутренний атрибут одинаково (`self.age = age` внутри `@property age`), ты создашь **бесконечную рекурсию**, и программа упадет с `RecursionError`.
2.  **Read-only свойства**: Если ты напишешь только `@property` без `.setter`, атрибут станет доступен только для чтения. Это отличный способ защитить важные данные от случайного изменения.
3.  **Вычисляемые свойства**: Свойства идеальны для того, чтобы не хранить лишние данные. Например, вместо хранения `first_name` и `last_name` отдельно, можно сделать свойство `full_name`, которое склеивает их на лету. Это гарантирует актуальность данных.
4.  **Обратная совместимость**: Свойства позволяют тебе начать с обычного публичного атрибута (`self.age = 25`), а позже, когда потребуется валидация, заменить его на `@property`, **не меняя код во всем проекте**. Для пользователя это всё так же `user.age`.

---

### ❓ FAQ (Частые вопросы)

**В: Зачем использовать `@property`, если можно просто написать метод `get_age()`?**
**О:** В Python считается не «питонячим» (unpythonic) использование геттеров и сеттеров в стиле Java. Свойства позволяют сохранить чистый интерфейс: пользователь работает с объектом так, будто это простые данные, но ты сохраняешь полный контроль над логикой.

**В: Не замедляет ли это работу программы?**
**О:** Да, вызов метода чуть медленнее, чем прямое обращение к атрибуту. Но в 99% бизнес-задач эта разница ничтожна по сравнению с пользой от безопасного кода и чистоты архитектуры.

**В: Можно ли использовать свойства для всех атрибутов подряд?**
**О:** Не стоит. Используй их только тогда, когда нужна логика (валидация, вычисление или лог). Если это простое хранение данных без правил — обычный атрибут лучше.

# 🧠 Шпаргалка: Методы класса (`@classmethod`) vs Статические методы (`@staticmethod`)

Если коротко: разница между ними в том, **что они «видят»** внутри класса. Обычный метод видит объект (`self`), `classmethod` видит класс (`cls`), а `staticmethod` не видит ничего из этого.

---

### 1. `@classmethod` (Метод класса)
Этот метод привязан к самому классу, а не к конкретному объекту. Его первым обязательным аргументом всегда идет `cls` — ссылка на сам класс.

*   **Зачем нужен:**
    1.  **Factory Methods (Фабричные методы):** Создание объектов альтернативными способами. Например, ты хочешь создать объект `User` не только по полям, но и, скажем, передав строку JSON.
    2.  **Изменение состояния класса:** Если нужно изменить атрибут, который общий для всех экземпляров (например, счетчик созданных объектов).

### 2. `@staticmethod` (Статический метод)
Это просто функция, которая живет внутри пространства имен класса. Она не получает ни `self`, ни `cls`. Она «заперта» в классе только для логической группировки.

*   **Зачем нужен:**
    1.  **Утилитарная функция:** Когда логика тесно связана с классом (например, валидация данных), но функции не нужно знать ничего о свойствах класса или объекта.
    2.  **Чистота кода:** Чтобы не плодить функции в глобальной области видимости, если они относятся только к этому классу.

---

### 💻 Код-демонстрация

```python
class Pizza:
    def __init__(self, ingredients):
        self.ingredients = ingredients

    # Обычный метод: работает с конкретной пиццей
    def __repr__(self):
        return f"Pizza({self.ingredients})"

    # --- CLASS METHOD (Фабрика) ---
    @classmethod
    def margherita(cls):
        """Создает пиццу с фиксированным набором ингредиентов."""
        # Мы используем cls, чтобы создать экземпляр текущего класса
        return cls(['mozzarella', 'tomato'])

    @classmethod
    def from_string(cls, ingredients_str):
        """Создает пиццу из строки: 'cheese,pepperoni'"""
        ingredients = ingredients_str.split(", ")
        return cls(ingredients)

    # --- STATIC METHOD (Утилита) ---
    @staticmethod
    def is_healthy(ingredients):
        """Просто проверяет список ингредиентов. Ей не важен класс Pizza."""
        bad_stuff = ['pineapple', 'extra_sugar']
        return not any(item in ingredients for item << bad_stuff)

# --- Использование ---

# 1. Обычное создание
p1 = Pizza(['cheese', 'mushrooms'])

# 2. Использование фабричного метода (classmethod)
p2 = Pizza.margherita() 
print(f"Factory method: {p2}") # Output: Pizza(['mozzarella', 'tomato'])

# 3. Создание из строки (classmethod)
p3 = Pizza.from_string("ham, onion, pepper")
print(f"From string: {p3}")

# 4. Использование утилиты (staticmethod)
# Мы передаем данные напрямую, метод не зависит от состояния объектов
print(f"Is p1 healthy? {Pizza.is_healthy(p1.ingredients)}") 
```

---

### ⚠️ Нюансы и "Подводные камни" (Senior Tips)

1.  **Наследование и `cls`:** Это киллер-фича `@classmethod`. Если ты создашь подкласс `class PepperoniPizza(Pizza)`, то при вызове `PepperoniPizza.margherita()`, аргумент `cls` будет указывать на `PepperoniPizza`, а не на базовый класс. Это позволяет фабрикам работать корректно с иерархией классов. Статический метод так не умеет — он "не знает", какой класс его вызвал.
2.  **Не злоупотребляй `@staticmethod`:** Если твой статический метод начинает зависеть от атрибутов класса, превращай его в `classmethod`. Если он просто делает расчеты и ему вообще плевать на класс — выноси его вообще за пределы класса (в модуль).
3.  **Память:** Статические методы и методы класса чуть более "легкие", так как не требуют передачи экземпляра (`self`), но разница в производительности в 99% случаев ничтожна. Главное — **семантика** (смысл кода).

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: В чем главное отличие `classmethod` от `staticmethod`?**
**О:** `classmethod` принимает первым аргументом ссылку на класс (`cls`), что позволяет работать с атрибутами класса и поддерживать наследование. `staticmethod` не получает никаких скрытых аргументов и ведет себя как обычная функция.

**В: Можно ли внутри `staticmethod` обратиться к `self`?**
**О:** Нет. У статического метода нет доступа к экземпляру объекта. Если тебе нужен доступ к атрибутам конкретной пиццы (например, её весу), используй обычный метод с `self`.

**В: Зачем использовать `@classmethod` для создания объектов, если можно просто написать обычную функцию вне класса?**
**О:** Во-первых, это инкапсуляция (логика создания принадлежит классу). Во-вторых, благодаря аргументу `cls`, фабричный метод будет работать правильно при наследовании, создавая объекты подклассов, а не базового класса.

**В: Когда лучше использовать `@staticmethod`?**
**О:** Когда у тебя есть вспомогательная логика (валидация, форматирование строк, математические расчеты), которая логически относится к теме класса, но ей не нужно состояние объекта или класса.

# 🛠 Шпаргалка: Исключения (Exceptions) в Python

**Исключение** — это событие во время выполнения программы, которое нарушает нормальный ход инструкций. Если его не обработать, программа аварийно завершится (crash).

### 1. Базовая конструкция: `try-except-else-finally`
Это фундамент. Важно понимать роль каждого блока.

```python
try:
    # Код, который может вызвать ошибку
    result = 10 / int(input("Введите число: "))
except ValueError:
    # Сработает, если пользователь ввел не число (например, "abc")
    print("Ошибка: Нужно ввести именно целое число!")
except ZeroDivisionError:
    # Сработает, если пользователь ввел 0
    print("Ошибка: На ноль делить нельзя!")
except Exception as e:
    # "Запасной аэродром" для всех остальных ошибок. 
    # 'as e' позволяет получить текст ошибки.
    print(f"Произошла непредвиденная ошибка: {e}")
else:
    # Сработает ТОЛЬКО если в блоке try НЕ возникло исключений.
    # Идеальное место для логики, которая зависит от успеха операции.
    print(f"Успех! Результат: {result}")
finally:
    # Сработает В ЛЮБОМ СЛУЧАЕ (была ошибка или нет).
    # Используется для очистки ресурсов: закрытия файлов, соединений с БД.
    print("Завершение операции (очистка ресурсов).")
```

### 2. Генерация исключений (`raise`)
Иногда мы сами должны сказать программе: «Стоп, здесь что-то не так!». Для этого используется `raise`.

```python
def set_age(age):
    if age < 0:
        # Выбрасываем стандартное исключение с кастомным сообщением
        raise ValueError("Возраст не может быть отрицательным!")
    return age
```

### 3. Кастомные исключения (Custom Exceptions)
В больших проектах важно создавать свои классы ошибок, чтобы отличить «бизнес-ошибки» от системных.

```python
class ValidationError(Exception):
    """Базовый класс для ошибок валидации в нашем приложении."""
    pass

class UserNotFoundError(ValidationError):
    """Ошибка, если пользователь не найден в базе."""
    pass

# Использование
raise UserNotFoundError("Пользователь с ID 42 не существует")
```

### ⚠️ Нюансы и «Подводные камни» (Senior Tips)

1.  **Никогда не используй "голый" `except:`**.
    *   `except:` (без указания типа) ловит вообще всё, включая `KeyboardInterrupt` (Ctrl+C). Это значит, что ты не сможешь остановить программу вручную. 
    *   **Правильно:** `except Exception:` или, что еще лучше, указывать конкретные ошибки (`ValueError`, `KeyError`).

2.  **Порядок имеет значение.**
    Python проверяет блоки `except` сверху вниз. Если ты первым поставишь `except Exception:`, то все остальные специфичные блоки ниже (например, `except ValueError:`) никогда не сработают, так как `Exception` их «перехватит».

3.  **Принцип "Try small".**
    Не запихивай весь свой код в один огромный блок `try`. Чем больше кода внутри `try`, тем сложнее понять, какая именно строка вызвала ошибку. Оборачивай только те строки, где реально может возникнуть ошибка.

4.  **Цепочки исключений (Exception Chaining).**
    Если ты ловишь одну ошибку и выбрасываешь другую, используй `from`. Это сохранит историю («traceback»), и ты увидишь, что стало первопричиной.
    ```python
    try:
        do_something()
    except ConnectionError as e:
        raise RuntimeError("Не удалось выполнить операцию") from e
    ```

### ❓ FAQ (Частые вопросы)

**В: В чем разница между SyntaxError и Exception?**
**О:** `SyntaxError` — это ошибка в структуре кода (забыл двоеточие, не закрыл скобку). Она обнаруживается *до* запуска программы. `Exception` — это ошибка во время работы (Runtime Error), когда синтаксис верный, но логика привела к тупику (например, деление на ноль).

**В: Зачем нужен блок `else`, если можно просто написать код после `try-except`?**
**О:** Это вопрос чистоты кода. Если ты поместишь дополнительный код в блок `try`, и он сам вызовет ошибку, то он попадет в блок `except`. Блок `else` гарантирует, что этот код выполнится только при *успешном* завершении блока `try`, не смешивая «опасный» код с «безопасным».

**В: Что произойдет, если внутри `finally` вызвать `return` или выбросить новую ошибку?**
**О:** Это "убьет" предыдущее исключение. Если в `try` возникла ошибка, но в `finally` ты сделал `return`, то программа просто тихо завершит выполнение функции, и оригинальная ошибка будет потеряна. Будь осторожен!

# 📂 Шпаргалка: Работа с файлами в Python

Работа с файлами — это взаимодействие с операционной системой. Главная задача здесь: эффективно прочитать/записать данные и **не оставить за собой мусора** (открытых дескрипторов файлов).

### 1. Золотое правило: Контекстный менеджер `with`
Забудь про ручное закрытие файла `f.close()`. Если программа упадет с ошибкой до того, как ты вызовешь `.close()`, файл останется «занятым» системой.

**Плохо:**
```python
f = open('data.txt', 'r')
# Если тут случится ошибка, файл не закроется!
print(f.read())
f.close()
```

**Хорошо (Senior Way):**
```python
with open('data.txt', 'r', encoding='utf-8') as f:
    data = f.read()
# Файл закроется автоматически, даже если внутри блока возникнет ошибка.
```

---

### 2. Режимы доступа (Modes)
Это критически важно. Ошибка в букве режима может привести к удалению данных.

| Режим | Название | Описание | Нюанс |
| :--- | :--- | :--- | :--- |
| `'r'` | **Read** | Только чтение. | Если файла нет — будет `FileNotFoundError`. |
| `'w'` | **Write** | Только запись. | **ВНИМАНИЕ:** Перезаписывает файл с нуля! Все старое удалится. |
| `'a'` | **Append** | Дозапись. | Добавляет данные в конец файла. Содержимое сохраняется. |
| `'x'` | **Exclusive** | Создание. | Создаст файл, но если он уже есть — выдаст ошибку. |
| `'b'` | **Binary** | Бинарный режим. | Используется для картинок, PDF, аудио (`'rb'`, `'wb'`). |
| `'t'` | **Text** | Текстовый режим | Режим по умолчанию. |
| `'+'` | **Update** | Чтение + Запись | Позволяет и читать, и писать в один поток. |

---

le### 3. Методы чтения и записи

#### Чтение (Reading)
1. `f.read()` — читает **весь** файл целиком в память. *Опасно для файлов размером 10 ГБ!*
2. `f.readline()` — читает одну строку.
3. `f.readlines()` — читает все строки и возвращает их списком.

**Senior Tip: Итерация по файлу.** Это самый эффективный способ. Python не загружает весь файл в RAM, а читает его построчно.
```python
with open('huge_file.txt', 'r') as f:
    for line in f:  # Читаем по одной строке за раз
        process(line)
```

#### Запись (Writing)
1. `f.write(string)` — записывает строку. Не добавляет `\n` автоматически!
2. `f.writelines(list_of_strings)` — записывает список строк.

---

### 4. Современный стандарт: `pathlib`
Забудь про старый модуль `os.path`. В современном Python для работы с путями используется `pathlib`. Это объектно-ориентированный подход.

```python
from pathlib import Path

file_path = Path("data") / "logs" / "today.txt"  # Умная склейка путей (работает и на Windows, и на Linux)

print(file_path.exists())  # Проверка существования
print(file_path.suffix)    # Получить расширение (.txt)
print(file_path.name)      # Имя файла с расширением
```

---

### 5. Нюансы и "Подводные камни" (Senior Insights)

*   **Encoding (Кодировка):** Всегда явно указывай `encoding='utf-8'`. Если не указать, Python возьмет системную кодировку (на Windows это может быть `cp1251`), и когда твой код запустят на Linux, всё «сломается» из-за спецсимволов.
*   **File Pointer (Указатель):** Представь, что внутри файла есть «курсор». Если ты сделал `.read()`, курсор встал в конец. Следующий `.read()` вернет пустоту. Используй `f.seek(0)`, чтобы вернуть курсор в начало.
*   **Размер имеет значение:** Никогда не делай `.read()` для файлов, размер которых может превысить твою оперативную память.

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Что произойдет, если открыть файл в режиме `'w'`, а он уже существует?**
**О:** Содержимое файла будет полностью стерто, и начнется запись с чистого листа.

**В: В чем разница между `f.read()` и `f.readlines()`?**

**В: Как безопасно проверить, существует ли файл, прежде чем его открывать?**
**О:** Используй `pathlib.Path('file.txt').exists()`. Это чище и современнее, чем `os.path.isfile`.

**В: Почему важно использовать `with`?**

# 📂 Шпаргалка: Форматы данных (Serialization & Deserialization)

**Суть:** Когда программа работает, данные живут в оперативной памяти в виде объектов Python (списки, словари, классы). Но чтобы сохранить их в файл или отправить по сети, их нужно превратить в последовательность байтов или строку. Этот процесс называется **сериализацией**, а обратный — **десериализацией**.

### 1. JSON (JavaScript Object Notation)
*Король веб-разработки и API.*

*   **Суть:** Текстовый формат, легко читаемый человеком и машиной. Основан на парах `ключ: значение`.
*   **Синтаксис:** Используем встроенный модуль `json`.
    *   `json.dumps(obj)` $\rightarrow$ объект в **строку**.
        *   `json.dump(obj, file)` $\rightarrow$ объект в **файл**.
    *   `json.loads(string)` $\leftarrow$ строка в **объект**.
        *   `json.load(file)` $\leftarrow$ файл в **объект**.
*   **⚠️ Нюансы (Senior level):**
    *   **Ограничение типов:** JSON поддерживает только: `dict`, `list`, `str`, `int`, `float`, `bool`, `None`. Ты **не можешь** напрямую сохранить `tuple`, `set` или `datetime`. При десериализации кортеж превратится в список.
    *   **Кодировка:** Всегда используй `utf-8`.

```python
import json

data = {"name": "Alice", "age": 30, "is_admin": True}

# Сериализация в строку
json_string = json.dumps(data, indent=4) # indent делает красивый отступ
# Сохранение в файл
with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f)
```

### 2. CSV (Comma-Separated Values)
*Стандарт для табличных данных и Excel.*

*   **Суть:** Плоский текстовый формат, где данные разделены запятой (или другим разделителем).
*   **Синтаксис:** Модуль `csv`.
    *   `csv.reader(file)` $\rightarrow$ читает строки как списки.
/    *   `csv.DictReader(file)` $\rightarrow$ читает строки как словари (используя заголовок первой строки как ключи).
*   **⚠️ Нюансы:**
    *   **Разделитель (Delimiter):** В Европе часто используют `;`, так как запятая — это десятичный разделитель. Всегда проверяй `delimiter=','`.
    *   **Сложные данные:** CSV не умеет хранить вложенные структуры. Только «плоские» таблицы.

```python
import csv

# Запись
with open("users.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "age"])
    writer.writeheader()
    writer.writerow({"name": "Bob", "age": 25})

# Чтение (как словарь)
with open("users.csv", mode="r") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["name"], row["age"])
```

### 3. Pickle
*Python-специфичный бинарный формат.*

*   **Суть:** Позволяет сохранять **любые** объекты Python (даже твои кастомные классы) в бинарном виде.
*   **Синтаксис:** Модуль `pickle`.
    *   `pickle.dump(obj, file)` / `pickle (load)`.
*   **❌ КРИТИЧЕСКИЙ НЮАНС (Security Warning):**
    *   **Никогда не десериализуй (unpickle) данные из ненадежных источников!** При загрузке файла с `pickle` может выполниться произвольный вредоносный код. Это дыра в безопасности уровня "Critical".
    *   **Не переносимо:** Файл, созданный в Python, сложно прочитать на Java или JS.

```python
import pickle

class User:
    def __init__(self, name): self.name = name

user_obj = User("Senior Dev")

# Сериализация (бинарный режим 'wb')
with open("user.pkl", "wb") as f:
    pickle.dump(user_obj, f)

# Десериализация (бинарный режим 'rb')
with open("user.pkl", "rb") as f:
    loaded_user = pickle.load(f)
    print(loaded_user.name)
```

# 🧠 Шпаргалка: Итераторы и Генераторы

Если коротко: **Итератор** — это «указатель», который умеет переходить к следующему элементу. **Генератор** — это «фабрика», которая создает элементы на лету, когда они тебе нужны.

---

### 1. Итерируемые объекты vs Итераторы
Это база, на которой валятся новички.

*   **Итерируемый объект (Iterable):** Это то, что можно перебрать в цикле `for`. У него есть метод `__iter__()`, который возвращает итератор. 
    *   *Примеры:* `list`, `str`, `tuple`, `dict`, `set`.
*   **Итератор (Iterator):** Это объект, который «помнит», на каком элементе он сейчас находится. У него есть метод `__next__()`, который возвращает следующий элемент, и метод `__iter__()` (который просто возвращает самого себя).

**Как это работает внутри:**
Когда ты пишешь `for x in my_list:`, Python делает следующее:
1. Вызывает `it = iter(my_list)` (получает итератор).
2. Постоянно вызывает `next(it)`.
3. Когда элементы заканчиваются, ловит исключение `StopIteration` и тихо завершает цикл.

---

### 2. Генераторы (Generators) — Магия `yield`
Генератор — это подвид итератора. Его не нужно создавать через классы, его можно написать как обычную функцию, но вместо `return` использовать ключевое слово **`yield`**.

**В чем профит?**
*   **Lazy Evaluation (Ленивые вычисления):** Генератор не считает все значения сразу и не хранит их в памяти. Он вычисляет следующее значение только в тот момент, когда ты его запросил.
*   **Экономия памяти:** Если тебе нужно обработать файл на 100 ГБ, ты не можешь загрузить его в `list`. Ты используешь генератор, который читает по одной строке.

**Пример:**
```python
def count_up_to(n):
    count = 1
    while count <= n:
        yield count  # Функция "замирает" здесь и отдает значение
        count += 1

counter = count_up_to(5)
print(next(counter)) # 1
print(next(counter)) # 2
```

---

### 3. Генераторные выражения (Generator Expressions)
Это «синтаксический сахар», похожий на List Comprehensions, но вместо квадратных скобок `[]` используются круглые `()`.

*   `[x**2 for x in range(10)]` $\rightarrow$ **List Comprehension** (сразу создает список в памяти).
*   `(x**2 for x <<in range(10))` $\rightarrow$ **Generator Expression** (создает объект-генератор).

---

### 4. Senior Nuances (Подводные камни) ⚠️

1.  **Одноразовость (Exhaustion):** Итераторы и генераторы — это «расходный материал». Как только ты прошел по ним циклом до конца, они становятся пустыми. Повторный цикл `for` по тому же объекту ничего не даст.
    *   *Решение:* Если нужны данные снова, либо создай новый генератор, либо сохрани результат в `list`.
2.  **Состояние (State):** Генератор хранит состояние всех локальных переменных. Это удобно для создания сложных последовательностей, но помни: если ты используешь генератор внутри функции, его состояние «заморожено» до следующего вызова.
3.  **Бесконечные последовательности:** С помощью генераторов можно создавать бесконечные циклы (например, поток данных из датчика), которые не «взорвут» твою оперативную память, потому что они выдают по одному значению за раз.

**В: В чем разница между `__iter__` и `__next__`?**
**О:** `__iter__` подготавливает объект к обходу (возвращает итератор), а `__next__` — это само действие по получению следующего элемента. Без `__iter__` ты не сможешь использовать объект в цикле `for`.

**В: Что произойдет, если вызвать `next()` на пустом генераторе?**
**О:** Выбросится исключение `StopIteration`. Именно на этом механизме строится остановка всех циклов `for`.

**В: Когда стоит использовать List Comprehension вместо Generator Expression?**
**О:** Используй `list`, если тебе нужно многократно обращаться к элементам по индексу или если тебе нужно сортировать/менять данные. Используй `generator`, если данных очень много (или они бесконечны) и тебе нужно просто пройтись по ним один раз (фильтрация, агрегация).

**В: Можно ли использовать `yield` в обычном методе класса?**
**О:** Да, такой метод будет называться методом-генератором. При вызове он вернет объект-генератор, который можно итерировать.

# 🧠 Тема: Рекурсия (Recursion)

### 💡 Суть простыми словами
**Рекурсия** — это когда функция вызывает саму себя. Представь матрешку: ты открываешь одну, а внутри точно такая же, но чуть меньше. Ты продолжаешь процесс, пока не дойдешь до самой маленькой матрешки, которую уже нельзя открыть.

В программировании рекурсия — это способ решения задачи путем разбиения её на более мелкие подзадачи того же типа.

### 🛠 Анатомия рекурсии
Любая правильная рекурсивная функция **обязана** состоять из двух частей:
1.  **Базовый случай (Base Case):** Условие выхода. Точка, где выполнение функции прекращается и начинается возврат ответов по цепочке вверх. Без него ты получишь бесконечный цикл и ошибку.
2.  **Рекурсивный шаг (Recursive Step):** Вызов функции с новыми, измененными аргументами, которые приближают нас к базовому случаю.

### 💻 Пример: Факториал ($n!$)
Факториал — это произведение всех чисел от $1$ до $n$.
*Математически: $5! = 5 \times 4 \times 3 \times $\dots \times 1$.*

```python
def factorial(n):
    # 1. Базовый случай: если n равно 1, возвращаем 1 (дальше открывать нечего)
    if n == 1:
        return 1
    
    # 2. Рекурсивный шаг: n * факториал предыдущего числа
    return n * factorial(n - 1)

print(factorial(5))  # Вывод: 120
```

### ⚠️ Нюансы и «Подводные камни» (Senior Level)

1.  **Стек вызовов (Call Stack):** Каждый раз, когда функция вызывает себя, Python создает новый «фрейм» в памяти (сохраняет локальные переменные и адрес возврата). Если рекурсия слишком глубокая, память закончится.
2.  **RecursionError:** В Python стоит предохранитель. Если глубина вызовов превысит лимит (обычно 1000), ты получишь `RecursкуsionError: maximum recursion depth exceeded`.
    *   *Как проверить лимит:* `import sys; print(sys.getrecursionlimit())`
    *   *Можно ли увеличить?* Можно через `sys.setrecursionlimit()`, но **не делай этого без крайней необходимости** — ты просто замаскируешь баг, который приведет к падению программы по памяти (Segmentation Fault).
3.  **Отсутствие Tail Call Optimization (TCO):** В некоторых языках (например, Haskell или Scala) есть оптимизация хвостовой рекурсии, которая позволяет делать бесконечную рекурсию без переполнения стека. **В Python её НЕТ.** Поэтому в Python глубокую рекурсию всегда лучше заменять циклом `while` или `for`.
4.  **Производительность:** Рекурсия часто медленнее циклов из-за накладных расходов на создание фреймов стека.

### 🚀 Как оптимизировать: Мемоизация
Если рекурсия делает много лишних вычислений (как в классической задаче на числа Фибоначчи), используй **мемоизацию** (кэширование результатов).

```python
from functools import lru_cache

@lru_cache(None)  # Магия: Python запоминает результаты прошлых вызовов
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

### ❓ FAQ (Частые вопросы на собеседовании)

**В: Чем рекурсия отличается от итерации (цикла)?**
**О:** Рекурсия — это самоподобие и декларативный подход (описываем *что* хотим получить). Итерация — это пошаговый процесс управления состоянием через циклы (описываем *как* идти по шагам). Рекурсия элегантнее для деревьев и графов, но итерация безопаснее для простых линейных задач.

**В: Что произойдет, если забыть базовый случай?**
**О:** Произойдет бесконечная рекурсия, которая будет плодить фреймы в стеке, пока Python не выбросит `RecursionError`.

**В: Когда стоит использовать рекурсию вместо цикла?**
**О:** Когда структура данных сама по себе рекурсивна. Классические примеры: обход папок и файлов на диске (дерево), обход деревьев (DOM в HTML, JSON), работа с графами или алгоритмы типа QuickSort/MergeSort.

**В: Как превратить рекурсию в цикл?**
**О:** С помощью использования собственного стека данных (структура `list` в Python). Мы имитируем поведение системы, вручную сохраняя задачи, которые нужно выполнить.

# 🧠 Шпаргалка: Метапрограммирование в Python

### 1. Суть концепции
Метапрограммирование — это способность программы рассматривать, манипулировать и изменять саму себя во время выполнения (runtime). В Python всё является объектом: функции, классы, типы данных. Раз всё есть объект, значит, мы можем менять поведение этих объектов «на лету».

### 2. Интроспекция (Introspection) — «Зрение» программы
Прежде чем что-то менять, нужно это увидеть. Интроспекция позволяет коду изучать структуру объектов.
*   `type(obj)` — узнаем, что это за тип.
*   `dir(obj)` — получаем список всех атрибутов и методов объекта.
*   `hasattr(obj, 'name')`, `getattr(obj, 'name')`, `setattr(obj, 'name', value)` — динамический доступ к атрибутам по их строковому имени. **Это база метапрограмми-рования.**
*   `isinstance(obj, Class)` — проверка на принадлежность к классу.

### 3. Декораторы (Decorators) — «Обертки»
Самый популярный инструмент. Декоратор — это функция, которая принимает другую функцию (или класс) и возвращает её измененную версию.
*   **Зачем:** Добавление логики (логирование, проверка прав, кэширование) без изменения исходного кода функции.
*   **Нюанс:** Всегда используй `functools.wraps`, чтобы не «затереть» метаданные оригинальной функции (её имя и docstring).

### 4. Динамическое управление атрибутами — «Магия имен»
Ты можешь перехватить момент, когда кто-то пытается обратиться к несуществующему или существующему атрибуту.
*   `__getattr__(self, name)`: Вызывается **только если** атрибут не найден обычным путем. Идеально для создания «прокси-объектов» или динамических API.
*   `__getattribute__(self, name)`: Вызывается **всегда**, при каждом обращении к любому атрибуту. 
    *   ⚠️ **Опасность:** Если внутри `__getattribute__` обратиться к `self.something`, ты вызовешь этот же метод снова $\rightarrow$ **бесконечная рекурсия**.
*   `__setattr__(self, name, value)`: Позволяет контролировать процесс присваивания значений. Можно запретить менять определенные поля или валидировать данные.

### 5. Метаклассы (Metaclasses) — «Завод по производству классов»
Если класс определяет, как ведут себя *объекты*, то метакласс определяет, как ведут себя *классы*. В Python класс сам является объектом, созданным метаклассом `type`.
*   **Как это работает:** Когда ты пишешь `class MyClass: ...`, Python вызывает метакласс, чтобы создать этот класс.
*   **`__new__` vs `__init__` в метаклассе:** 
    *   `__new__` — создает сам объект класса (меняет структуру класса до его появления).
    *   `__init__` — инициализирует уже созданный класс.
*   **Зачем это нужно Senior-у:** Для автоматической регистрации классов в реестре, принудительной проверки наличия определенных методов у наследников или автоматического добавления атрибутов во все подклассы.

### 6. Динамическое выполнение кода — «Опасная зона»
*   `eval(expression)`: Вычисляет строку как Python-выражение и возвращает результат.
*   `exec(code_block)`: Выполняет блок кода (целые инструкции).
*   ⚠️ **Security Warning:** Никогда не используй `eval` или `exec` с данными, пришедшими от пользователя. Это прямой путь к взлому системы (RCE — Remote Code Execution).

# 🧵 Шпаргалка: Многопоточность (`threading`)

### 🧠 Суть простыми словами
Представь, что ты повар на кухне. 
*   **Однопоточность:** Ты ставишь чайник, стоишь и ждешь, пока он закипит, прежде чем начать резать хлеб.
*    **Многопоточность (Threading):** Ты поставил чайник и, пока он греется, начал резать хлеб. Ты всё еще один (один процесс), но ты переключаешь внимание между задачами, чтобы не простаивать.

В Python **threading** позволяет выполнять несколько задач «одновременно» (точнее, очень быстро переключаясь между ними), когда программа тратит время на ожидание чего-то внешнего.

---

### ⚠️ Главный нюанс: GIL (Global Interpreter Lock)
Это то, о чем спрашивают на каждом собеседовании. В Python есть «замок» (GIL), который позволяет только одному потоку выполнять байт-код в один момент времени.
*   **Следствие:** Потоки в Python **не могут** использовать несколько ядер процессора для вычислений. 
*   **Вывод:** `threading` — это не про параллельные математические расчеты, а про эффективное ожидание.

---

### ✅ Когда использовать (I/O-bound задачи)
Используй потоки, если программа «ждет»:
1.  Запросы к API или сетевые запросы (`requests`, `urllib`).
2.  Чтение/запись файлов на диск.
3.  Работа с базой данных.
4.  Ожидание ответа от пользователя.

### ❌ Когда НЕ использовать (CPU-bound задачи)
Если нужно считать числа, обрабатывать изображения или сжимать видео — потоки сделают только хуже из-lock-а GIL. Для этого нужен модуль `multiprocessing`.

---

### 🛠 Основной инструментарий

#### 1. Создание и запуск
```python
import threading
import time

def task(name, delay):
    print(f"Поток {name} начал работу")
    time.sleep(delay)  # Имитация ожидания (I/O)
    print(f"Поток {name} закончил")

# Создаем потоки
t1 = threading.Thread(target=task, args=("A", 2))
t2 = threading.Thread(target=task, args=("B", 1))

t1.start() # Запуск
t2.start()

t1.join()  # Ждем, пока t1 завершится (программа не пойдет дальше, пока t1 не доделает работу)
t2.join()  # Ждем t2
print("Все задачи выполнены")
```

####  দখল 2. Синхронизация: Lock (Замок)
Когда два потока одновременно пытаются изменить одну и ту же переменную, возникает **Race Condition** (состояние гонки). `Lock` позволяет разрешить доступ к ресурсу только одному потоку.

```python
lock = threading.Lock()
counter = 0

def increment():
    global counter
    for _ in range(100000):
        with lock: # Только один поток может войти в этот блок кода одновременно
            counter += 1
```

#### 3. Daemon Threads (Демон-потоки)
Это «фоновые» потоки. Если основной поток (main) завершается, все daemon-потоки убиваются автоматически. Полезно для фоновых задач вроде мониторинга или очистки кэша.
`t = threading.Thread(target=func, daemon=True)`

---

### 💀 Опасные зоны (Pitfalls)
1.  **Race Condition:** Забытый `Lock` при работе с общими данными. Результат будет непредсказуемым.
2.  **Deadlock (Взаимная блокировка):** Поток А ждет Lock, который держит Поток Б. Поток Б ждет Lock, который держит Поток А. Программа зависла навсегда.
3.  **Сложность отладки:** Ошибки в потоках часто проявляются случайно и их крайне трудно воспроизвести.

---

### ❓ FAQ (Частые вопросы)

**В: Можно ли с помощью threading ускорить вычисления матрицы в Python?**
**О:** Нет. Из-за GIL потоки будут бороться за один и тот же процессорный ресурс, и накладные расходы на переключение контекста даже замедлят процесс. Используй `multiprocessing`.

**В: Что такое `join()`?**
**О:** Это метод, который говорит основному потоку: «Стой здесь и жди, пока целевой поток не закончит свою работу». Без него main-поток может завершиться раньше, чем потоки успеют что-то сделать.

**В: Является ли `list.append()` потокобезопасным?**
**О:** В стандартной реализации CPython — да (атомарная операция). Но полагаться на это в сложном коде — плохая практика. Если логика сложнее одного `append`, всегда используй `Lock`.

**В: В чем разница между Threading и Multiprocessing?**
**О:** 
*   `Threading`: Один процесс, общая память, подходит для I/O (ожидания).
*   `Multiprocessing`: Много процессов, у каждого своя память, подходит для CPU (вычислений), обходит GIL.

# 🧠 Шпаргалка: Multiprocessing (Многопроцессорность)

### 🎯 Суть темы
**Multiprocessing** — это способ заставить Python выполнять задачи **параллельно**, используя несколько ядер вашего процессора. 

В отличие от *Threading* (многопоточности), где все потоки живут в одном процессе и делят одну память, *Multiprocessing* создает **отдельные процессы**. У каждого процесса свой собственный экземпляр интерпретатора Python и своя собственная область памяти.

### 🚀 Главное отличие: GIL и CPU-bound задачи
Это база. В Python есть **GIL (Global Interpreter Lock)**. Он — как один охранник, который пропускает к процессору только один поток в один момент времени. 
*   **Threading** не может обойти GIL. Поэтому потоки хороши для задач **I/O-bound** (ожидание ответа от сети, чтение диска).
*   **Multiprocessing** обходит GIL, потому что каждый процесс — это новый «охранник» и свой собственный интерпретатор. Это единственный путь для **CPU-bound** задач (тяжелые вычисления, обработка изображений, математика, криптография).

---

### 🛠 Основные инструменты

1.  **`Process`**: Базовый класс для создания отдельного процесса. Ты вручную управляешь его жизненным циклом (`start()`, `join()`).
2.  **`Pool`**: «Пул» рабочих процессов. Самый удобный инструмент, когда у тебя есть список задач и ты хочешь раскидать их по свободным ядрам (например, метод `.map()`).
3.  **`Queue` / `Pipe`**: Средства общения между процессами (**IPC** — Inter-Process Communication). Поскольку память у процессов разная, они не могут просто так поменять одну переменную. Нужно передавать сообщения через очереди.
4.  **`Lock`**: Объект для синхронизации, если процессы все же пытаются достучаться до какого-то общего ресурса (например, файла или Shared Memory).

---

### ⚠️ Подводные камни и нюансы (Senior Tips)

*   **🚨 Обязательный `if __name__ == "__main__":`**: Это критично! На Windows и macOS при создании нового процесса Python заново импортирует твой скрипт. Если не использовать эту проверку, ты создашь бесконечную рекурсию создания процессов, и система «ляжет».
*   **📦 Проблема Pickling (Сериализация)**: Все данные, которые ты передаешь из главного процесса в дочерний (и обратно), должны быть **pickleable**. Это значит, что Python должен уметь превратить объект в байты. Лямбда-функции или некоторые сложные объекты могут не пройти через этот «транспорт».
/
*   **🐌 Накладные расходы (Overhead)**: Создание процесса — это дорого. Запуск нового процесса занимает время и память. Если задача длится 0.001 сек, то запуск процесса займет больше времени, чем сама задача. Не используй multiprocessing для микро-задач.
*   **📉 Память**: Каждый процесс копирует (в логическом смысле) ресурсы родителя. Если у тебя массив на 4 ГБ и ты запустишь 8 процессов, ты рискуешь мгновенно съесть всю оперативную память сервера.

### 💻 Код: Сравнение подходов

```python
import multiprocessing
import time

def heavy_computation(n):
    """Тяжелая математическая задача (CPU-bound)"""
    print(f"Начинаю расчет для {n}")
    result = sum(i * i for i in range(n))
    return result

if __name__ == "__main__":
    numbers = [10**7, 10**7 + 1, 10**7 + 2, 10**7 + 3]

    # --- Вариант 1: Использование Pool (Рекомендуемый для задач) ---
    print("--- Запуск через Pool ---")
    start_time = time.time()
    with multiprocessing.Pool(processes=multiprocessing.cpu_count()) as pool:
        results = pool.map(heavy_computation, numbers)
    print(f"Результаты: {results}")
    print(f"Время Pool: {time.time() - start_time:.2f}s\n")

    # --- Вариант 2: Использование Process (Для независимых задач) ---
    print("--- Запуск через Process ---")
    start_time = time.time()
    processes = []
    for n in numbers:
        p = multiprocessing.Process(target=heavy_computation, args=(n,))
        processes.append(p)
        p.start()

    for p in processes:
        p.join()  # Ждем завершения каждого процесса
    print(f"Время Process: {time.time() - start_time:.2f}s")
```

**В: Когда я выберу Multiprocessing, а когда Threading?**
**О:** Если задача ждет внешнего ресурса (сеть, БД, диск) — **Threading**. Если задача нагружает процессор расчетами — **Multiprocessing**.

**В: Можно ли процессам иметь общую переменную?**
**О:** Напрямую — нет, у них разные области памяти. Но можно использовать `multiprocessing.Value` или `multiprocessing.Array` (для примитивов) или передавать данные через `Queue`.

**В: Что такое Zombie Process?**
**О:** Это процесс, который завершил работу, но его запись всё еще висит в таблице процессов ОС, потому что родитель не вызвал `.join()`, чтобы «забрать» код завершения. Всегда делай `.join()` или используй контекстные менеджеры/Pool.

**В: Почему Multiprocessing может работать медленнее, чем один поток?**
**О:** Из-за **Overhead**. Если задача слишком легкая, время на создание процесса, копирование памяти и сериализацию данных (pickling) превысит выгоду от параллельного выполнения.

# ⚡️ Шпаргалка: Асинхронное программирование (`asyncio`)

### 🧠 Суть простыми словами
Представь повара на кухне.
*   **Синхронный подход:** Повар поставил чайник и **стоит смотрит на него**, пока тот не закипит. Только потом начинает резать бутерброд. (Процессор просталоивает).
*   **Многопоточность (Threading):** Мы наняли второго повара. Теперь на кухне двое, но они толкаются локтями и делят один нож. (Дорого по памяти, сложно управлять).
*   **Асинхронность (Asyncio):** Повар поставил чайник, **включил таймер и пошел резать бутерброд**. Когда таймер звякнул, он вернулся к чайнику. Один повар, но процесс не прерывается из-за ожидания.

**Ключевое правило:** Асинхронность идеальна для **I/O-bound** задач (сеть, файлы, БД), но бесполезна для **CPU-bound** задач (сложные вычисления, обработка видео).

---

### 🛠 Основные понятия
1.  **Coroutine (Корутина):** Специальная функция, которую можно поставить «на паузу». Объявляется через `async def`.
2.  **Event Loop (Цикл событий):** «Диспетчер» или тот самый повар. Он следит за всеми задачами и переключает их, когда одна ждет ответа.
3.  **Awaitable:** Объект, который можно использовать с `await` (корутины, Tasks, Futures).
4.  **Task (Задача):** Обертка над корутиной, которая говорит циклу событий: «Запусти эту задачу как можно скорее».

---

### 📝 Синтаксис и пример

```python
import asyncio

# Это корутина
async def fetch_data(id, delay):
    print(f"🚀 Задача {id}: Начинаю ждать {delay} сек...")
    await asyncio.sleep(delay)  # Не блокирует поток, а отдает управление циклу
    print(f"✅ Задача {id}: Готово!")
    return f"Данные {id}"

async def main():
    # Создаем задачи (запускаем их конкурентно)
    task1 = asyncio.create_task(fetch_data(1, 3))
    task2 = asyncio.create_task(fetch_data(2, 1))

    print("--- Запуск задач ---")
    
    # Ждем завершения обеих задач
    # gather соберет результаты в список
    results = await asyncio.gather(task1, task2)
    
    print(f"--- Результаты: {results} ---")

# Точка входа в асинхронную программу
if __name__ == "__main__":
    asyncio.run(main())
```

### ⚠️ Нюансы и «Подводные камни» (Senior Level)

1.  **Смертельная ошибка — Блокирующий код:** Если ты внутри `async def` вызовешь обычный `time.sleep(5)` или тяжелую математическую функцию, **ты остановишь весь Event Loop**. Весь твой асинхронный сервис «умрет» и будет ждать эти 5 секунд, не переключаясь на другие задачи.
    *   *Решение:* Используй только асинхронные аналоги (`asyncio.sleep`, `aiohttp` вместо `requests`).
2.  **Библиотеки имеют значение:** Ты не можешь использовать стандартную библиотеку `requests` в асинхронном коде, потому что она блокирует поток. Тебе нужны `aiohttp`, `httpx` или `motor` (для MongoDB).
3.  **CPU-bound задачи:** Если нужно считать математику, `asyncio` не поможет. Используй `loop.run_in_executor` с `ProcessPoolExecutor`, чтобы вынести вычисления в отдельный процесс.
4.  **Забытый `await`:** Если ты вызвал корутину без `await`, она не выполнится. Ты просто получишь объект корутины, но код внутри не запустится.

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Чем `asyncio` отличается от `threading`?**
**О:** `Threading` использует переключение контекста на уровне ОС (прерывает поток в любой момент), что дорого и может привести к Race Condition. `Asyncio` — это кооперативная многозадачность: задача сама говорит «я подожду», отдавая управление. Это гораздо легче и позволяет держать тысячи соединений одновременно.

**В: Что делает `asyncio.gather()`?**
**О:** Он запускает несколько корутин одновременно и ждет их завершения, возвращая список результатов в том же порядке, в котором были переданы аргументы.

**В: Можно ли использовать асинхронность для обработки тяжелого изображения?**
**О:** Нет. Это CPU-bound задача. Асинхронность не добавит вычислительной мощности процессору. Она лишь поможет эффективно ждать ответа от сети. Для изображений используй `multiprocessing`.

**В: Что такое `await`?**
**О:** Это инструкция интерпретатору: «Поставь выполнение этой функции на паузу, освободи поток для других задач, и вернись сюда, когда результат этого ожидания будет готов».

# 🧠 Шпаргалка: Global Interpreter Lock (GIL)

### 📌 Суть простыми словами
Представь, что Python — это огромная кухня с кучей поваров (**потоков/threads**). У каждого повара есть свои руки и навыки, но на этой кухне есть всего **один единственный нож** (**GIL**). Чтобы нарезать овощи, повар обязан взять этот нож. Даже если у тебя 10 поваров, одновременно резать может только один. Остальные стоят и ждут своей очереди.

**GIL — это мьютекс (замок), который позволяет только одному потоку управлять интерпретатором Python в один момент времени.**

### 🛠 Почему он существует? (Нюансы)
Ты можешь спросить: *"Зачем нам такой тормоз?"*. Ответ кроется в управлении памятью.
1.  **Reference Counting (Подсчет ссылок):** Python использует счетчик ссылок для очистки памяти. Если два потока одновременно изменят счетчик одного и того же объекта, это может привести к утечке памяти или внезапному удалению объекта, который еще используется. GIL защищает этот процесс от "состояния гонки" (race condition).
2.  **Простота интеграции:** Благодаря GIL написание расширений на C стало намного проще, так как разработчикам не нужно было заботиться о сложной синхронике внутри каждого C-модуля.

### ⚠️ Главное последствие: CPU-bound vs I/O-bound
Это критически важно для выбора инструмента разработки:

1.  **CPU-bound задачи (Вычисления):** Задачи, нагружающие процессор (математика, обработка видео, архивация). **Threading бесполезен.** Из-за GIL потоки будут только мешать друг другу, тратя время на переключение контекста.
    *   *Решение:* `multiprocessing` (создает отдельные процессы, у каждого свой интерпретатор и свой GIL).
2.  **I/O-bound задачи (Ожидание):** Задачи, где программа большую часть времени ждет (сетевые запросы, чтение диска, работа с БД). **Threading работает отлично!** Когда один поток ждет ответа от сервера, он *отпускает* GIL, позволяя другому потоку выполнять работу.
    *   *Решение:* `threading` или `asyncio`.

### 💻 Демонстрация на коде

```python
import threading
import time
import multiprocessing

def heavy_computation():
    """Задача, нагружающая CPU (просто считаем сумму)"""
    count = 0
    for i in range(10**7):
        count += i
    return count

if __mu_time = time.time()

# --- Сценарий 1: Последовательное выполнение ---
start = time.time()
heavy_computation()
heavy_computation()
print(f"Sequential time: {time.time() - start:.2f}s")

# --- Сценарий 2: Threading (Потоки) ---
# Мы надеемся на многопоточность, но GIL нас затормозит
start = time.time()
t1 = threading.Thread(target=heavy_computation)
t2 = threading.Thread(target=heavy_computation)
t1.start(); t2.start()
t1.join(); t2.join()
print(f"Threading time (CPU-bound): {time.time() - start:.2f}s") 
# Результат будет почти таким же, как в Sequential, или даже медленнее!

# --- Сценарий 3: Multiprocessing (Процессы) ---
# Каждый процесс имеет свой GIL и свой интерпретатор
start = time.time()
p1 = multiprocessing.Process(target=heavy_computation)
p2 = multiprocessingint.Process(target=heavy_computation)
p1.start(); p2.start()
p1.join(); p2.join()
print(f"Multiprocessing time: {time.time() - start:.2f}s")
# Результат будет значительно быстрее (если ядер > 1)
```

**В: Можно ли обойти GIL в Python?**
**О:** Да, тремя способами:
1. Использовать модуль `multiprocessing` (создание новых процессов).
2. Писать критические по скорости участки кода на C/C++/Rust (библиотеки типа NumPy или Pandas работают вне GIL, так как освобождают его во время тяжелых вычислений).
3. Использовать альтернативные реализации Python (например, Jython или IronPython, где GIL нет, но там слабее экосистема библиотек).

**В: Влияет ли GIL на `asyncio`?**
**О:** Напрямую — нет. `asyncio` работает в **одном** потоке. Он не борется с GIL, он просто эффективно управляет ожиданием (I/O) внутри этого единственного потока.

**В: А что слышно про удаление GIL?**
**О:** Это горячая тема! В рамках **PEP 703** начата работа по реализации "free-threaded" Python (Python без GIL). В версии 3.13 появились экспериментальные возможности запуска без GIL. Но это сложный процесс, который может замедлить однопоточную производительность.

**В: Если я использую `requests` в 10 потоках, будет ли это быстрее?**
**О:** Да! Потому что `requests` — это I/O-bound задача. Пока один поток ждет сетевой пакет, GIL освобождается для другого потока. Это классический пример использования threading.

# 🧩 Шпаргалка: Аннотации типов (Type Hinting)

### 💡 Суть
Python — язык с **динамической типизацией**. Это значит, что интерпретатор не проверяет типы переменных во время выполнения кода. Аннотации типов (PEP 484) — это способ «подсказать» разработчику и инструментам (IDE, линтеры) ожидания от кода.

**Важное правило:** Аннотации **не влияют** на работу программы. Если ты напишешь `x: int = "привет"`, Python не выдаст ошибку при запуске. Это лишь документация, которую может проверить специальный инструмент — **Mypy**.

---

### 🛠 Базовый синтаксис

#### 1. Переменные
```python
age: int = 25
name: str = "Alex"
is_active: bool = True
price: float = 99.9
```

#### 2. Функции (Аргументы и Возвращаемое значение)
Самое важное место для аннотаций.
```python
def greet(name: str, age: int) -> str:
    return f"Привет, {name}, тебе {age}!"
```

---

### 📦 Модуль `typing` и современные стандарты

Раньше всё брали из модуля `typing`, но в Python 3.9+ и 3.10+ синтаксис стал чище.

#### 1. Коллекции (Python 3.9+)
Теперь можно использовать встроенные типы вместо `List`, `Dict` из модуля `typing`.
```python
# Старый стиль: from typing import List; names: List[str] = []
# Новый стиль (рекомендуемый):
names: list[str]  # Список строк
scores: dict[str, int]  # Словарь: ключ — строка, значение — число
coordinates: tuple[float, float]  # Кортеж из двух чисел
```

#### 2. Union и Optional (Объединение типов)
Когда переменная может быть одного из нескольких типов.
*   **Python 3.10+ (Стиль пайп `|`):**
    ```python
    def process(data: str | int) -> None:  # Принимает либо str, либо int
        pass

    def find_user(user_id: int) -> str | None: # Может вернуть строку или None
        ...
    ```
*   **Старый стиль (до 3.10):** `from typing import Union, Optional`
    ```python
    from typing import Union, Optional
    def process(data: Union[str, int]) -> None: ...
    def find_user(user_id: int) -> Optional[str]: ... # То же самое, что str | None
    ```

#### 3. Специальные типы
*   `Any`: «Святой Грааль» хаоса. Разрешает любой тип. Используй только в крайнем случае, иначе смысл аннотаций теряется.
*   `Callable`: Для функций. `func: Callable[[int, int], int]` — функция, принимающая два `int` и возвращающая `int`.
*   `Literal`: Ограничение конкретными значениями.
    ```python
    from typing import Literal
    def set_mode(mode: Literal["read", "write"]) -> None: ...
    # mode = "delete"  <-- Mypy подсветит ошибку!
    ```
*   `Protocol` (Duck Typing на стероидах): Позволяет описывать интерфейсы. Если объект имеет нужный метод — он подходит.

### ⚠️ Нюансы и «Подводные камни» (Senior Tips)

1.  **Type Erasure (Стирание типов):** В рантайме (во время работы программы) информация о типах из аннотаций **исчезает**. Ты не можешь написать `if isinstance(x, list[int])` — это вызовет ошибку, так как `list[int]` существует только для статических анализаторов.
2.  **Производительность:** Аннотации практически не влияют на скорость выполнения кода. Но их обработка (если ты используешь библиотеки вроде `Pydantic`) может занимать время.
3.  **Не переусердствуй:** Не нужно аннотировать каждую локальную переменную внутри функции. Это превращает код в «спагетти» из типов. Аннотируй **интерфейсы**: аргументы функций, возвращаемые значения и публичные атрибуты классов.
4.  **Mypy — твой лучший друг:** Пиши аннотации только для того, чтобы запускать `mypy .` в CI/CD. Без статического анализатора твои аннотации — просто красивые комментарии.

# 📦 Шпаргалка: Управление пакетами в Python

### 🧠 Суть (The Big Picture)
В Python есть два разных понятия, которые новички часто путают:
1.  **Установка пакетов:** Скачивание стороннего кода из интернета (из репозитория **PyPI**) и добавление его в твой проект.
2.  **Управление окружением:** Создание изолированной «песочницы» (виртуальной среды), чтобы проект А не сломал проект Б, используя разные версии одной и той же библиотеки.

**Золотое правило Senior-разработчика:** *Никогда не устанавливай пакеты в глобальную область видимости Python. Всегда используй виртуальное окружение.*

---

### 🛠 Инструментарий (The Toolbox)

#### 1. Уровень "Базовый" (Standard Library & Pip)
*   **`pip`**: Стандартный менеджер пакетов. Умеет скачивать, устанавливать и удалять библиотеки.
    *   `pip install <package>` — установка.
/ `pip uninstall <package>` — удаление.
    *   `pip freeze > requirements.txt` — создание «слепка» всех установленных библиотек с их точными версиями.
*   **`venv`**: Встроенный модуль для создания виртуальных окружений.
    *   `python -m venv .venv` — создать окружение в папке `.venv`.
    *   `source .venv/bin/activate` (Linux/macOS) или `.venv\Scripts\activate` (Windows) — активировать среду.

#### 2. Уровень "Профи" (Modern Dependency Management)
Современный стандарт — это переход от разрозненных файлов к единому конфигу **`pyproject.toml`** (PEP 518).
*   **Poetry**: Самый мощный инструмент на сегодня. Он не только устанавливает пакеты, но и управляет зависимостями, версиями и сборкой твоего проекта. Создает файл `poetry.lock`, который гарантирует, что у всех разработчиков в команде установлены *абсолютно идентичные* версии библиотек.
*   **Pipenv**: Гибрид `pip` и `venv`. Автоматизирует создание окружений и использует `Pipfile`.

---

### ⚠️ Нюансы и "Подводные камни"

1.  **Dependency Hell (Ад зависимостей):** Ситуация, когда Библиотека А требует `Requests v2.0`, а Библиотека Б требует `Requests v3.0`. Решается использованием инструментов с разрешением конфликтов (Lock-файлы в Poetry).
2.  **Версионность (Semantic Versioning):** 
    *   `package==1.2.3` — жесткая привязка (безопасно, но трудно обновлять).
    *   `package>=1.2.0` — гибко, но опасно (обновление может сломать код).
    *   `package~=1.2.0` — совместимая версия (обновит только патчи, например, 1.2.1, но не 1.3.0). **Рекомендуемый подход.**
3.  **Requirements.txt vs Lock-файл:** `requirements.txt` часто содержит лишь список «хотелок», а `lock-файл` (в Poetry или Pipenv) — это детальный список всех под-зависимостей с их хеш-суммами для безопасности.

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Зачем нужно виртуальное окружение, если можно просто всё ставить в систему?**

**В: В чем разница между `pip freeze` и `pip list`?**
**О:** `pip list` просто показывает список установленных пакетов в удобном виде. `pip freeze` выводит их в формате, готовом для записи в `requirements.txt` (с указанием точных версий через `==`), что критически важно для воспроизводимости среды.

**О:** Это современный стандарт конфигурации Python-проектов. Раньше настройки были разбросаны по `setup.py`, `setup.cfg`, `requirements.txt`. **В: Что делать, если я установил пакет, но `import` не работает?**
**О:** Скорее всего, ты установил пакет в глобальное окружение или в одно виртуальное, а запускаешь скрипт, используя другое (не активированное) окружение. Проверь путь к интерпретатору через `which python` (Linux) или `where python` (Windows).

# 🧪 Тестирование в Python: Шпаргалка Senior-уровня

### 🎯 Суть тестирования
Тестирование — это процесс верификации (соответствует ли код спецификации) и валидации (решает ли код задачу пользователя). Его цель — уменьшить стоимость ошибки. Исправить баг на этапе написания теста стоит $1, на этапе продакшена — $1000.

---

### 🏗 Уровни тестирования (The Testing Pyramid)
В хорошем проекте тесты распределены пирамидально:
1.  **Unit Tests (Модульные):** Проверяют одну маленькую функцию или класс в полной изоляции. Самые быстрые и дешевые.
2.  **Integration Tests (Интеграционные):** Проверяют, как несколько модулей работают вместе (например, код + база данных).
3.  **E2E / End-to-End (Сквозные):** Имитируют действия реального пользователя (нажать кнопку $\rightarrow$ получить ответ от API). Самые медленные и хрупкие.

---

### 🛠 Инструментарий Python
1.  **`unittest`**: Встроенный фреймворк (стандарт библиотеки). Использует подход xUnit (как в Java). Тяжеловесный, требует написания классов.
2.  **`pytest`**: **Золотой стандарт индустрии.** Позволяет писать тесты простыми функциями. Обладает мощнейшей экосистемой плагинов и удобными `fixtures`.
3.  **`doctest`**: Проверяет примеры кода прямо в документации (docstrings). Хорошо для простых примеров, но не для сложной логики.
4.  **`coverage.py`**: Инструмент для измерения покрытия кода тестами (какие строки кода были запущены, а какие — нет).

---

### 🎭 Изоляция и Mocking (Заглушки)
Главное правило Unit-теста: **он не должен зависеть от внешнего мира** (интернета, БД, файловой системы). Если тест падает из-за того, что упал сервер Google, — это плохой тест.

*   **Mock (Мок):** Объект, который имитирует поведение реального объекта. Мы можем сказать: «Когда вызовут метод `get_user`, верни вот этот словарь».
*   **`unittest.mock`**: Мощный модуль Python. 
    *   `patch`: Заменяет реальный объект на Mock во время теста.
    *   `MagicMock`: Умная заглушка, которая умеет имитировать даже магические методы (`__str__`, `__iter__`).

---

### 💎 Best Practices (Золотые правила)
1.  **AAA Pattern (Arrange, Act, Assert):**
    *   **Arrange:** Подготовка данных и окружения.
    *   **Act:** Вызов тестируемой функции.
    *   **Assert:** Проверка результата.
2.  **Тесты должны быть детерминированными:** Один и тот же код всегда должен давать один и тот же результат теста. Никаких `random` или `datetime.now()` без фиксации (mocking).
3.  **Независимость:** Тест А не должен зависеть от того, прошел ли тест Б.
4.  **Single Responsibility:** Один тест проверяет одну конкретную вещь. Не делайте «тест-монстров».
5.  **Fast & Fast & Fast:** Юнит-тесты должны летать. Если тесты идут 20 минут, разработчики перестанут их запускать.

### ❓ FAQ (Частые вопросы на собеседованиях)

**В: Чем `pytest` лучше, чем `unittest`?**
**О:** В `pytest` меньше шаблонного кода (boilerplate). Вместо сложных классов и методов `assertEqual`, ты используешь обычный `assert`. Также в `pytest` есть мощная концепция **fixtures** — переиспользуемых компонентов для подготовки данных.

**В: Что такое TDD (Test Driven Development)?**
**О:** Это методология, где цикл разработки выглядит так: 1. Пишем тест, который падает $\rightarrow$ 2. Пишем минимально необходимый код, чтобы тест прошел $\rightarrow$ 3. Рефакторим код. Это заставляет писать тестируемый и чистый код.

**В: Что такое "Regression Testing" (Регрессионное тестирование)?**
**О:** Это повторное выполнение тестов при каждом изменении кода, чтобы убедиться, что новые правки не сломали то, что работало раньше.

**В: Как протестировать функцию, которая делает запрос к API?**
**О:** Нельзя делать реальный сетевой запрос. Нужно использовать `unittest.mock.patch`, чтобы подменить библиотеку `requests` (или `httpx`) на заглушку, которая вернет заранее подготовленный JSON-ответ с нужным статус-кодом.

**В: 100% покрытие кода тестами — это цель?**
**О:** Нет. Это ловушка. Можно покрыть тестами все строки кода, но не проверить граничные условия или логические связи. Важна **качество** проверок (edge cases), а не просто количество закрашенных строк в отчете coverage.

# 🪵 Шпаргалка: Логирование в Python

### 🚫 Почему `print()` — это зло?
В разработке `print()` допустим, но в **production** он бесполезен. 
1. Его нельзя гибко выключить (придется удалять код).
2. Он не разделяет события по важности.
le 3. У него нет контекста (времени, уровня ошибки, имени модуля).
4. Он не умеет писать в разные места одновременно (в консоль и в файл).

---

### 🏗 Архитектура модуля `logging`
Логирование — это не одна функция, а конвейер из четырех компонентов:

1.  **Logger (Логгер):** Точка входа. Тот самый объект, который ты вызываешь в коде (`logger.info(...)`).
2.  **Handler (Обработчик):** Определяет, *куда* пойдет лог (в консоль, в файл, в сетевой запрос, в Sentry).
3.  **Formatter (Форматтер):** Определяет, *как* будет выглядеть строка (дата, уровень, сообщение, имя файла).
4.  **Filter (Фильтр):** (Редко, но метко) Позволяет более тонко отсеивать записи по сложным условиям.

---

### 📊 Уровни логирования (Levels)
Иерархия важности (от низшего к высшему):

| Уровень | Название | Когда использовать |
| :--- | :--- | :--- |
| `DEBUG` | Отладка | Детальная информация для поиска багов (переменные, шаги алгоритма). |
| `INFO` | Инфо | Подтверждение, что всё идет по плану (запуск сервиса, завершение задачи). |
| `WARNING` | Предупреждение | Что-то пошло не так, но программа продолжает работать (low disk space). |
| `ERROR` | Ошибка | Серьезная проблема, часть функционала сломана (ошибка API, база данных упала). |
| `CRITICAL` | Критическая ошибка | Фатальный сбой, программа не может продолжать работу. |

---

### 🛠 Практическая реализация

#### 1. Быстрый старт (для скриптов)
Если тебе нужно просто писать в файл без сложной настройки:
```python
import logging

logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(levelname)s - %(message)s',
    filename='app.log', # Если убрать — будет в консоль
    filemode='a'        # 'a' - дописывать, 'w' - перезаписывать
)

logging.info("Приложение запущено")
```

#### 2. Профессиональный подход (для приложений)
В серьезных проектах мы создаем логгер для каждого модуля и настраиваем разные обработчики.

```python
import logging

# 1. Создаем логгер
logger = logging.getLogger("my_app")
logger.setLevel(logging.DEBUG) # Общий порог для логгера

# 2. Создаем форматтер
formatter = logging.Formatter('%(name)s - %(levelname)s - %(message)s')

# 3. Создаем Handler для консоли (выводит всё от INFO и выше)
console_handler = logging.StreamHandler()
console_handler.setLevel(logging.INFO)
console_handler (formatter)

# 4. Создаем Handler для файла (пишет всё, включая DEBUG)
file_handler = logging.FileHandler("debug.log")
file_handler.setLevel(logging.DEBUG)
file_handler.setFormatter(formatter)

# 5. Добавляем обработчики к логгеру
logger.addHandler(console_handler)
logger.addHandler(file_handler)

# Использование
logger.debug("Это попадет только в файл")
logger.info("Это попадет и в консоль, и в файл")
```

---

### ⚠️ Нюансы и "Подводные камни" (Senior Tips)

1.  **⚠️ Проблема переполнения диска:** Никогда не используй простой `FileHandler` в долгоживущих сервисах. Файл вырастет до терабайта и убьет сервер. Используй **`RotatingFileHandler`** (ротация по размеру) или **`TimedRotatingFileHandler`** (ротация по времени, например, новый файл каждый день).
2.  **⚠️ Производительность (Lazy Evaluation):** 
    *   ❌ Плохо: `logger.debug(f"User data: {expensive_function()}")` — функция выполнится **всегда**, даже если уровень логов установлен на INFO.
    *   ✅ Хорошо: `logger.debug("User data: %s", expensive_data)` — Python вычислит строку только если уровень DEBUG активен.
3.  **⚠️ Конфигурация в библиотеках:** Если ты пишешь библиотеку, **никогда** не вызывай `logging.basicConfig()`. Это изменит логирование во всем приложении пользователя. Просто создавай логгер: `logger = logging.getLogger(__name__)`.
4.  **⚠️ Структурированное логирование:** В современных облаках (Docker, Kubernetes) лучше писать логи в формате **JSON**. Это позволяет системам вроде ELK или Splunk мгновенно парсить поля (user_id, error_code) без мучений с регулярками.

# 🧠 Шпаргалка: Регулярные выражения в Python (`re`)

**Суть:** Regex — это язык описания шаблонов для поиска и манипуляции текстом. В Python всё крутится вокруг модуля `re`.

### 1. Основы синтаксиса (Символы-метасимволы)
*   `.` — Любой символ, кроме переноса строки.
*   `^` — Начало строки.
*   `$` — Конец строки.
*   `\` — Экранирование (используй `\\`, чтобы найти сам символ `\`).
*   `|` — Логическое «ИЛИ» (например, `cat|dog`).

### 2. Наборы символов (Character Classes)
*   `\d` — Любая цифра `[0-9]`.
*   `\D` — Всё, кроме цифр.
*   `\w` — Буквы, цифры и подчеркивание `[a-zA-Z0-9_]`.
*   `\W` — Всё, кроме «словесных» символов.
*   `\s` — Пробельные символы (пробел, табуляция, перенос строки).
*   `\S` — Всё, кроме пробелов.
*   `[abc]` — Любой из указанных символов (`a`, `b` или `c`).
*   `[^abc]` — Любой символ, **кроме** `a`, `b` или `c`.

### 3. Квантификаторы (Сколько раз повторять?)
*   `*` — 0 или более раз.
*   `+` — 1 или более раз.
*   `?` — 0 или 1 раз (делает символ «необязательным»).
*   `{n}` — Ровно `n` раз.
*   `{n,m}` — От `n` до `m` раз.

> **⚠️ Важный нюанс: Жадность vs Ленивость**
> По умолчанию все квантификаторы **жадные**. Они пытаются захватить как можно больше текста. 
> Пример: строка `<div>Hello</div>`. Шаблон `<.*>` заберет всё от первого `<` до последнего `>`. 
> Чтобы сделать поиск «ленивым» (до ближайшего совпадения), добавь `?`: `<.*?>` — захватит только `<div>`.

### 4. Группировка и извлечение
*   `(abc)` — **Захватывающая группа**. Позволяет выделить часть шаблона, чтобы потом её достать.
*   `(?:abc)` — **Незахватывающая группа**. Группирует символы для применения квантификатора, но не сохраняет их отдельно (экономит память).
*   `(?P<name>abc)` — **Именованная группа**. Самый «чистый» способ: ты обращаешься к результату по имени `name`, а не по индексу.

### 5. Основные функции модуля `re`
*   `re.search(pattern, string)` — Ищет **первое** совпадение во всей строке. Возвращает объект Match или `None`.
*   `re.match(pattern, string)` — Ищет совпадение **только в самом начале** строки. (Частая ловушка для новичков!).
*   `re.findall(pattern, string)` — Находит **все** совпадения и возвращает их в виде списка строк.
*   `re.finditer(pattern, string)` — То же, что `findall`, но возвращает **итератор** с объектами Match (эффективно для больших текстов).
*   `re.sub(pattern, replacement, string)` — Заменяет найденные совпадения на новую строку.
*   `re.split(pattern, string)` — Разрезает строку по шаблону.

### 6. Флаги (Настройка поведения)
*   `re.IGNORECASE` (или `re.I`) — Игнорировать регистр (`A` == `a`).
*   `re.MULTILINE` (или `re.M`) — Позволяет `^` и `$` работать с началом и концом каждой строки, а не всей строки целиком.
*   `re.DOTALL` (или `re.S`) — Делает так, чтобы точка `.` захватывала и символы переноса строки `\n`.

---

### 💡 Senior Pro-Tips (Нюансы)

1.  **Всегда используй Raw Strings (`r"..."`)**: При написании паттернов всегда ставь префикс `r`. Это говорит Python: «Не интерпретируй обратные слэши сам, отдай их в Regex как есть». Без этого `\n` превратится в перенос строки еще до того, как попадет в движок Regex.
    *   *Плохо:* `"\\d+"`
    *   *Хорошо:* `r"\d+"`
2.  **Сложность (ReDoS)**: Будь осторожен с вложенными квантификаторами типа `(a+)+`. На специально подготовленной строке это может вызвать бесконечный цикл вычислений и «повесить» твой сервер (Regular Expression Denial of Service).

### ❓ FAQ (Частые вопросы)

**В: В чем разница между `re.match()` и `re.search()`?**
**О:** `match` проверяет только самое начало строки. Если совпадение находится в середине, `match` вернет `None`. `search` сканирует всю строку до первого нахождения.

**В: Как мне достать только ID из строки вида `user_id: 12345`?**
**О:** Используй именованную группу: `r"user_id: (?P<id>\d+)"`. После поиска ты сможешь вызвать `match.group('id')`.

**В: Что делать, если в моем тексте много переносов строк, и точка `.` не находит их?**
**О:** Используй флаг `re.DOTALL`. Он заставляет точку «видеть» символы новой строки.

**В: Как заменить все цифры в строке на символ `#`?**
**О:** `re.sub(r'\d', '#', text)`.

# 🌐 Шпаргалка: Работа с API и сетью в Python

Работа с сетью — это всегда работа с **ненадёжной средой**. Сеть может моргнуть, сервер может зависнуть, а API может прислать мусор вместо ожидаемого JSON. Твоя задача — написать код, который это предсказывает.

## 1. Основы HTTP (Что мы передаем)
Прежде чем писать код, нужно понимать протокол:
*   **Методы (Verbs):**
    *   `GET` — получение данных (не должен менять состояние сервера).
    *   `POST` — создание нового ресурса.
    *   `PUT` — полное обновление ресурса.
    *   `PATCH` — частичное обновление ресурса.
    *   `DELETE` — удаление.
*   **Коды ответов (Status Codes):**
    *   `2xx` (Success) — всё ок (например, `200 OK`, `201 Created`).
    *   `3xx` (Redirection) — сервер просит тебя пойти по другому адресу.
    *   `4xx` (Client Error) — ты накосячил (`400 Bad Request`, `401 Unauthorized`, `403 Forbidden`, `404 Not Found`).
    *   `5xx` (Server Error) — сервер «умер» или сломался (`500 Internal Server Error`).
*   **Заголовки (Headers):** Метаданные. Самые важные: `Content-Type` (тип данных), `Authorization` (твой пропуск), `User-Agent` (кто ты такой).

---

## 2. Библиотека `requests` (Синхронный стандарт)
Самая популярная библиотека для простых задач. Она блокирующая (ждет ответа, пока не получит его).

**Базовый паттерн:**
```python
import requests

url = "https://api.example.com/v1/data"
headers = {"Authorization": "Bearer YOUR_TOKEN"}
params = {"id": 123}  # Добавится в URL как ?id=123

try:
    response = requests.get(url, headers=headers, params=params, timeout=5)
    
    # Важнейший метод! Выбросит исключение, если код ответа 4xx или 5xx
    response.raise_for_status() 
    
    data = response.json()  # Парсим JSON в словарь Python
    print(data)

except requests.exceptions.HTTPError as errh:
    print(f"Http Error: {errh}")
except requests.exceptions.ConnectionError as errc:
    print(f"Error Connecting: {errc}")
except requests.exceptions.Timeout as errt:
    print(f"Timeout Error: {errt}")
except requests.exceptions.RequestException as err:
    print(f"Something went wrong: {err}")
```

**Нюанс (Senior Tip):** Никогда не используй `requests` без параметра `timeout`. Если сервер «зависнет» и не будет закрывать соединение, твой скрипт/сервис тоже зависнет навсегда.

---

## 3. Библиотека `httpx` и `aiohttp` (Асинхронный подход)
Если тебе нужно сделать 100 запросов, делать их по очереди через `requests` — это преступление против производительности. Используй асинхронность.

*   **`httpx`** — современный стандарт. Имеет почти такой же интерфейс, как `requests`, но поддерживает `async/await`.
*   **`aiohttp`** — более низкоуровневый и мощный, часто используется в высоконагруженных системах.

**Пример на `httpx`:**
```python
import asyncio
import httpx

async def fetch_data(url):
    async with httpx.AsyncClient() as client:
        response = await client.get(url)
        return response.json()

async def main():
    urls = ["https://api.github.com", "https://httpbin.org/get"]
    # Запускаем все запросы одновременно!
    tasks = [fetch_data(url) for url in urls]
    results = await asyncio.gather(*tasks)
    print(results)

asyncio.run(main())
```

---

## 4. Работа с данными: `json` vs `data`
В методах `POST/PUT` есть путаница, которую часто допускают джуны:
*   `requests.post(url, json={'key': 'value'})` — **Правильно**. Библиотека сама превратит словарь в JSON-строку и поставит заголовок `Content-Type: application/json`.
*   `requests.post(url, data={'key': 'value'})` — **Опасно**. Отправит данные как `application/x-www-form-urlencoded` (как обычную форму на сайте).

---

## 5. Безопасность и Best Practices
1.  **Никаких ключей в коде!** Используй `.env` файлы и библиотеку `python-dotenv`. Ключи API должны подтягиваться из переменных окружения (`os.getenv`).
2.  **Retry Logic (Повторные попытки):** Сеть нестабильна. Используй библиотеку `tenacity`, чтобы автоматически повторять запрос, если он упал по таймауту.
3.  **Session objects:** Если делаешь много запросов к одному хосту, используй `requests.Session()`. Это позволяет переиспользовать TCP-соединение (Keep-Alive), что в разы ускоряет работу.

## ❓ FAQ (Частые вопросы на собеседованиях)

**В: В чем разница между `401 Unauthorized` и `403 Forbidden`?**
**О:** `401` означает, что сервер не знает, кто ты (ты не предъявил паспорт/токен). `403` означает, что сервер тебя узнал, но тебе запрещено входить именно в эту «комнату» (нет прав доступа).

**В: Что такое `raise_for_status()` и зачем он нужен?**
**О:** По умолчанию `requests` не выдает ошибку, если пришел ответ `404` или `500`. Он просто вернет объект ответа. `raise_for_status()` заставляет программу упасть с исключением, что позволяет правильно обработать ошибку в блоке `try-except`.

**В: Почему важно использовать `Session` в `requests`?**
**О:** Без `Session` каждый запрос — это новое «рукопожатие» (TCP handshake) с сервером. С `Session` соединение остается открытым, что экономит время и ресурсы процессора/сети.

**В: Как передать API-ключ в запросе?**
**О:** Обычно либо в заголовке (`headers={'X-API-Key': '...'}`), либо как параметр в URL (`params={'api_key': '...'}`). Всегда проверяй документацию конкретного API.
